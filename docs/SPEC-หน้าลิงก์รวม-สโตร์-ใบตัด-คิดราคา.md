# SPEC — หน้ารวม "สโตร์ ↔ ใบตัด ↔ คิดราคา 4.0" (เจ้าของสั่ง 1 ก.ย.69)

## โจทย์จากเจ้าของ (คำต่อคำ)

> ขอไม่เอาแก้ใน csv ละ คือมันแก้หลายรอบไม่จบไม่สิ้น ไม่เริ่มตรวจสักที เอาเป็นแก้ในเว็บแทนได้ไหม
> หน้า 🔍 เทียบคิดราคา 4.0 ↔ ใบตัด ค่อนข้างดูง่ายเขียนชัดเจน มีรหัส
> อยากให้สามารถแก้ไขรหัส เพิ่มรายการได้ในหน้านั้น พร้อมลิงก์สต็อกให้ดูด้วย
> เช่น รหัสสโตร์ JR00377 ก็ให้จิ้มดูได้ว่า JR00377 คืออะไรในสโตร์เพื่อตรวจสอบ
> สิ่งที่ต้องทำเพิ่มคือ add ทุกงานเข้าไปให้ครบเพื่อตรวจได้
> ... 🔍 เทียบคิดราคา 4.0 ↔ ใบตัด และ ตรวจการผูกสโตร์ ↔ คิดราคา 4.0 ต้องเป็นหน้าเดียวกันด้วยซ้ำ
> เพราะชั้นจะลิงก์ทุกอย่างให้ตรงกัน ทั้ง สโตร์ ใบตัด คิดราคา
> คุณไปออกแบบหน้านี้มาใหม่ ให้อัพเดทแก้ง่ายๆ เอาอัพเดทแก้ขนาดตัดได้ด้วยนะ
> ... ถ้าแก้ ต้องแก้ไปถึงคิดราคา 4.0 และสโตร์ด้วย ไม่ได้แก้ลอยๆ

## ทำไม 2 หน้าถึงขัดกัน (ต้นเหตุที่เจ้าของเจอ)

| | หน้าเทียบใบตัด | หน้าตรวจผูกสโตร์ |
|---|---|---|
| ถามคำถามว่า | "คิดราคากับใบตัดใช้ของเหมือนกันไหม" | "รหัสนี้มีตัวตนในสโตร์ไหม" |
| เทียบด้วย | รหัสเส้น/รหัสอุปกรณ์ 2 ฝั่ง | ค้นรหัสในตาราง `stock_items` |
| เลยเกิดกรณี | รหัส F7864 ตรงกันเป๊ะ → **เขียว** | สโตร์ไม่มีแถว F7864 → **ไม่ผูก** |

**ทั้งคู่พูดถูก แต่ตอบคนละคำถาม** → รวมเป็นหน้าเดียวที่ 1 แถว = 1 วัสดุ แล้วมี **3 ช่องความจริง**
เคียงกัน: `คิดราคา 4.0` · `ใบตัด` · `สโตร์` เห็นครบในบรรทัดเดียวว่าขาดตรงไหน

## สถาปัตยกรรม — จุดตายที่ต้องเข้าใจก่อนเขียนโค้ด

**สูตรทั้งหมดอยู่ใน "ซอร์สโค้ด" ไม่ใช่ฐานข้อมูล**
- คิดราคา 4.0 → `src/lib/calculator40/products.mjs`
- ใบตัด → `src/lib/cutlist/products.ts`

เว็บที่ deploy แล้ว **แก้ไฟล์ตัวเองไม่ได้** → "แก้ในเว็บ" ต้องทำผ่าน **ชั้นทับค่า (override) ในฐานข้อมูล**
ที่เอนจินอ่านมาประกบตอนรัน

```
ซอร์ส (สูตรตั้งต้น)  +  ตารางทับค่าใน DB  =  สูตรที่ใช้จริง
     products.mjs          calc_line_overrides         ทุกหน้า
```

**ต้องประกบที่จุดเดียว** แล้วทุกหน้าได้เหมือนกัน — จุดนั้นคือที่ที่ทั้ง 3 หน้าเรียกอยู่แล้ว:
`buildPriceOverride()` / `applyPriceOverride()` ใน `src/lib/calculator40/stock-link.ts`
(ผู้ใช้: `calculator40/page.tsx` · `calculator40/compare/page.tsx` · `calculator40/stock-audit/page.tsx`)

> ⚠ ห้ามให้หน้าใหม่มีสูตรของตัวเอง — กฎเดิมของโปรเจกต์: "แก้ต้นทางที่เดียวเปลี่ยนทั้งเว็บ"

## ตารางใหม่ (migration 0134)

```sql
create table public.calc_line_overrides (
  id           bigint generated always as identity primary key,
  product_id   text    not null,          -- id รุ่นใน products.mjs เช่น 'awning'
  scope        text    not null,          -- 'calc' = ฝั่งคิดราคา · 'cut' = ฝั่งใบตัด
  match_key    text    not null,          -- รหัส (B####/JR#####) ถ้าไม่มีรหัสใช้ 'name:<ชื่อ>'
  -- ค่าที่ทับ (null = ไม่ทับ ใช้ของเดิม)
  set_sku      text,                      -- เปลี่ยนรหัสสโตร์/รหัสเส้น
  set_qty      text,                      -- สูตรจำนวนใหม่ (ข้อความสูตรเดียวกับในซอร์ส)
  set_len      text,                      -- สูตรความยาว/ขนาดตัดใหม่ (ฝั่งใบตัด)
  set_price    numeric(14,2),             -- ราคาสำรองใหม่
  -- แถวที่ "เพิ่มเอง" (ไม่มีในซอร์ส)
  is_added     boolean not null default false,
  item_name    text,
  unit         text,
  disabled     boolean not null default false,   -- ปิดแถวที่ซอร์สมีแต่ไม่ใช้แล้ว
  note         text    not null default '',
  created_by   uuid references auth.users(id),
  created_at   timestamptz not null default now(),
  updated_at   timestamptz not null default now(),
  unique (product_id, scope, match_key)
);
```

RLS: อ่านได้ทุก role ที่เข้าคิดราคาได้ · เขียนได้เฉพาะ ADMIN + role ที่ `can(role,'jobs','write')`

## หน้าใหม่ — `/calculator40/link`

### หัวหน้า
เลือก **รุ่น** (ครบทุกรุ่น 54 ไม่ใช่แค่ 17 ที่เทียบใบตัดได้) + กว้าง/สูง/จำนวนบาน/รูปแบบ/สี
+ ปุ่ม **"ไล่ทุกรูปแบบ"** (สุ่มหลายชุดแบบเดียวกับตัวออกรายงาน) เพื่อไม่ให้ของที่ใช้เฉพาะบางรูปแบบหลุด

### ตารางหลัก — 1 แถว = 1 วัสดุ

| คอลัมน์ | ที่มา |
|---|---|
| สถานะ | ป้ายสี (ดูด้านล่าง) |
| ชื่อรายการ | ชื่อจากสูตร |
| **รหัส** | แก้ได้ในที่ (inline edit) → เขียน `set_sku` |
| **คิดราคา 4.0** | จำนวน · ราคา/หน่วย · ยอด |
| **ใบตัด** | จำนวนชิ้น · **ความยาวตัด (แก้ได้)** → `set_len` |
| **สโตร์** | ชื่อจริงในสโตร์ · ราคา · คงเหลือ · ปุ่มเปิดดู |
| ปุ่ม | แก้ · ปิดแถว · ลบ override |

### ป้ายสถานะ (ยึดชุดเดียวกับรายงาน CSV ที่ทำไว้แล้ว)
`✓ ผ่าน` · `🔴 ต้องแก้` · `🟠 ต้องเติม` · `🔵 เช็คว่าคิดเกินไหม` · `🟣 ยังไม่ได้ตรวจ` · `🟡 ต้องเคาะ` · `⚪ ดูเฉย ๆ`

### ลิงก์สโตร์
กดรหัส `JR00377` → **แผงด้านข้าง (drawer)** โชว์ ชื่อ · หมวด · สี · ราคา/หน่วย · คงเหลือ · ผู้ขาย
+ ลิงก์ไปหน้าสโตร์เต็ม — **ไม่เด้งออกจากหน้า** จะได้ตรวจต่อได้

## สิ่งที่ต้อง "คิดเผื่อ" (เจ้าของสั่งให้คิดเผื่อ)

1. **ผลกระทบก่อนเซฟ** — เปลี่ยนรหัส/จำนวน = ทุนขยับ ต้องโชว์ "ทุนเดิม → ทุนใหม่ (±X บาท)" ก่อนกดยืนยัน
   (บทเรียนทั้งโปรเจกต์: ห้ามขยับเงินเงียบ ๆ)
2. **ประวัติ + ย้อนกลับ** — ทุก override เก็บ `created_by`/`updated_at` + ปุ่ม "คืนค่าเดิม" (ลบ override)
3. **กันพิมพ์รหัสมั่ว** — รหัสที่กรอกต้องมีจริงในสโตร์ ไม่มี = เตือน (ไม่บล็อก ตามนิสัย "ห้ามฟิก")
   แต่ต้องเห็นชัดว่ากำลังผูกกับของที่ไม่มีตัวตน
4. **ไม่พังใบเสนอเก่า** — ใบเสนอที่ออกไปแล้วเก็บ `calc_recipe` + ราคาของตัวเอง override ต้องไม่ย้อนไปแก้
5. **สโตร์ยังไม่มีของ** → ปุ่ม "สร้างในสโตร์" จากหน้านี้เลย (แต่ **ต้องให้เจ้าของกดเอง** —
   เจ้าของเคยสั่งห้ามผู้ช่วยสร้างของในสโตร์เอง เพราะเสี่ยงซ้ำ) → เปิดฟอร์มกรอกให้ ไม่สร้างอัตโนมัติ
6. **ตัวตรวจเดิมต้องยังเขียว** — `verify-r40` 407 · `sweep-compare` 87 · `verify-compare-cut` 176 ·
   `verify-stock-audit` 126 · `verify-alu-qty` 34 ห้ามแดงสักตัว
7. **override ต้องมีเทสของตัวเอง** — `scripts/verify-line-overrides.mjs`
   (ไม่มี override = ผลเท่าเดิมเป๊ะ · มี override = เปลี่ยนตามที่สั่งเท่านั้น ไม่หลุดไปรุ่นอื่น)
8. **1,000-row cap** — ดึงสต็อกต้อง `fetchAllPaged` เสมอ
9. **RBAC** — คนที่เห็นราคาทุนไม่ได้ (`canSeeCost` false) ต้องไม่เห็นคอลัมน์ราคา
10. **ห้ามใส่ข้อความไทยใน HTTP header** (กฎเดิมของโปรเจกต์)
