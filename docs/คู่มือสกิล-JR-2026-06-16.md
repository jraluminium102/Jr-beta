## 🔄 ลำดับงานจริง (เริ่มกลุ่มใหม่ยันปิดงาน)
1. **เริ่มกลุ่มใหม่** → พิมพ์ "ทำกลุ่ม G_" → **new-product-group** พาทำ (เรียก draft-ux-g + product-test-cards ให้เอง) ทีละสเตป รอพี่เคาะ
2. ได้ดราฟ+PDF+ใบส่ง dev → **ส่งแชท dev** แก้ index.html (1 ธง 1 commit)
3. **dev แก้เสร็จ** → พิมพ์ "ตรวจงาน G_" → **check-dev-vs-draft** เดินครบ → รวม 🔴 เป็นใบสั่ง dev รอบเดียว
4. dev แก้ 🔴 → ตรวจซ้ำ จน 🔴 = 0 = จบ

## 🔁 โฟลหลายแชท A↔B — คำสั่งภาษาคน (พี่นัทไม่เก่งคอม · มติ 16 มิ.ย.)
หลายแชทช่วยกัน · **แชท A (หลายตัว) = ตรวจ+เตรียมโค้ด** (READ-ONLY) · **แชท B = ช่างแก้ index.html คนเดียว**
> ⚠️ กฎเดียวที่ต้องรู้: "ช่างแก้โค้ดมีคนเดียว ณ เวลาหนึ่ง" — แชท A เตรียมพร้อมกันได้ · แชท B แก้ทีละงาน (อย่าให้ 2 แชทแก้พร้อมกัน ชนพัง)

|---|---|
| "เก็บเป็นก้อนก่อน ยังไม่ส่ง" | แชทจดทุกอย่างที่เคาะลงรายการ (ไม่ใช้ความจำ) |
| "ในก้อนมีอะไรบ้าง" | โชว์รายการสะสม เช็คว่าครบ |

## ⭐ หลักร่วม JR — ทุกสกิลยึด (สิ่งที่พี่นัทชอบ)
1. **ห้ามเดาราคา** — ยึดเลขจาก index.html / engine / REF เท่านั้น · ไม่ชัวร์ติดป้าย "(เช็คซ้ำ)"
2. **verify เบราว์เซอร์จริง** — ห้ามเคลม "ผ่าน" จาก jsdom · ต้องเปิด preview กดเองก่อน
3. **อธิบายภาษาคน** — ไม่เอาศัพท์อังกฤษห้วนๆ (เช่น ❌"o-dfm missing" ✅"ช่องดรอปพื้นหาย (โค้ด o-dfm)") · ตัวเลขบอกความหมาย ("ขยับ +4,000 = แพงขึ้น")
4. **สเปกขัดกัน → เลือกอันใหม่สุดเอง** · ไม่ชัวร์ → ถามพร้อม **ref** (ไฟล์+บรรทัด/มติวันไหน) ห้ามถามลอยๆ
5. **ทีละสเตป รอเคาะ · ทำทีละกลุ่ม** — ไม่ลุยรวด ไม่ข้ามกลุ่ม/ข้ามแชท (งานใครงานมัน)
6. **READ-ONLY index.html** — เจอผิด = ออกใบสั่งให้ dev แก้ · รวม 🔴 เป็นใบสั่งรอบเดียว (ไม่แก้กระจาย)
