ภาพรวม: ปัญหาที่พบ + วิธีแก้

ตรวจหน้า "รายการ" ในระบบ (index.html) โฟกัสชุดกั้นห้องกระจก (กลุ่ม 6) พบ friction 2 จุดหลักที่ทำให้คนกรอกสับสนบนมือถือ:

ปัญหา 1 — สี/กระจก ซ้ำกัน 2 ชั้น (เห็นค่าเดิม 2 ที่ ไม่รู้อันไหนคุมอะไร)
  • ชั้นบน: กล่องฟ้า #global-color-row — "สีอลูมิเนียม (ทั้งใบ)" + "กระจก (ทั้งใบ)"
  • ชั้นล่าง: กล่องเหลือง .gh-set-color-row inject โดย refreshSet() — "สีอลู (ทั้งห้อง)" + "กระจก (ทั้งห้อง)"
  • ทั้งคู่ sync ค่าเดียวกันตลอด (ถ้าไม่มีการ override) → user เห็น dropdown สองคู่ค่าเหมือนกัน ไม่เข้าใจ hierarchy
ปัญหา 2 — ออปชั่นบาน "หายหมด" (จริงๆ พับ 3-4 ชั้น)
  • ชั้น 1: collapseOthers() ~L2301 → การ์ด .ch ได้ class="ch collapsed" เมื่อเพิ่มบานใหม่ หรือกดบานอื่น
  • ชั้น 2: refreshSet() ~L1953-1954 set _det.open=false บน <details> wrapper ของ .i-opts → "⚙ ตัวเลือกเพิ่มเติม" พับ
  • ชั้น 3: หมวดออปชั่น (.gh-opt-cat-det) ใน groupGHOpts() ~L1796 → open=false ยกเว้นหมวดที่ตั้ง open:true
  • ผลรวม: กว่าจะเห็นออปชั่นต้อง กดขยายการ์ด → กด "⚙" → กดเปิดหมวด = 3-4 tap

ปัญหา 1 — สี/กระจก ซ้ำ 2 ชั้น: root cause + ทางแก้

Root cause (บรรทัดที่ dev ต้องดู)

Elementบรรทัดในโค้ดพฤติกรรม
#global-color-row L309-319 กล่องฟ้า render ใน HTML ตายตัว — แสดงตลอดเวลาในการ์ด "รายการ"
.gh-set-color-row L1909-1921 ใน refreshSet() inject กล่องเหลืองเมื่อชุดมี GH (group 6) — วางก่อน .set-parts · sync ค่าจาก colorOpts()/glassOpts() เหมือนกัน
syncGHColor() L1923-1934 เมื่อเปลี่ยน gh-color-sel → overwrite ทุก ch กลุ่ม 6 ใน set นั้น
syncGlobalColor() L1717-1723 เมื่อ global เปลี่ยน → skip ch กลุ่ม 6 ที่มี gh-set-color-row (ให้ GH master win) → ถูกต้อง แต่ไม่ได้ sync gh-set-color-sel ให้ตาม global ด้วย ทำให้ค่าค้างเดิม

UX ที่เสนอ (After — ดูดราฟ)

Pattern: Collapsed summary → Expand on demand
  • ปกติ: แสดงกล่องส้มบางๆ 1 บรรทัด "สี/กระจกห้องนี้: ตามทั้งใบ · [สีอบขาว] [กระจกเขียว 6 มม.]" พร้อมปุ่ม "แก้เฉพาะห้องนี้ ▾"
  • กดปุ่ม → ขยาย dropdown 2 ช่อง พร้อม badge "แตกต่างจากทั้งใบ" เมื่อค่าต่างกัน
  • เมื่อ global เปลี่ยน → sync ค่า gh dropdown + อัปเดต summary text
  • ผล: ไม่เห็น dropdown ซ้อน dropdown ในสภาพปกติ

ปัญหา 2 — ออปชั่นพับ 3-4 ชั้น: root cause + ทางแก้

Root cause (บรรทัดที่ dev ต้องดู)

ชั้นCode / บรรทัดพฤติกรรม

UX ที่เสนอ (After — ดูดราฟ)

Pattern: การ์ดกั้นห้องไม่พับ + ออปชั่นสำคัญดันขึ้นฟอร์มหลัก
  1. การ์ด GH ไม่เข้า collapseOthers: เมื่อ GH set อยู่ → ข้ามการ์ดที่ .i-group === '6' ใน collapse loop
  2. details ไม่ปิดสำหรับ GH: ใน refreshSet() L1954 เพิ่ม guard: if(isGH) _det.open=true; else _det.open=false;
  3. ออปชั่นสำคัญ inline: "ชนิดการเปิด" + "ราง" ดันขึ้นฟอร์มหลัก (ไม่อยู่ใน opts) — ดูดราฟ: inline-block สีฟ้าเหนือช่องขนาด
  4. หมวด 🚪 เปิดตั้งแต่ต้น: CATS entry สำหรับ GH: {key:'🚪 ชนิด / การเปิด', open:true, ...} แล้วอยู่ — ถูกแล้ว · แต่ถูกบังด้วยชั้น 1+2 → fix ชั้น 1+2 ก่อน

Code change สำหรับ dev

// === แก้ชั้น 1: collapseOthers — ข้ามการ์ด GH ===
// L2301 (function collapseOthers)
function collapseOthers(active){
  document.querySelectorAll('#items .ch').forEach(function(ch){
    if(ch===active) return setChCollapsed(ch, false);
    // *** เพิ่ม: การ์ดกลุ่ม 6 ใน set ที่มี GH → ไม่พับ ***
    var isGH = (ch.querySelector('.i-group')||{}).value === '6';
    var inGHSet = isGH && ch.closest('.setbox') &&
                  ch.closest('.setbox').querySelector('.gh-set-color-row');
    if(inGHSet) return; // *** ไม่พับการ์ดกั้นห้อง ***
    setChCollapsed(ch, true);
  });
}

// === แก้ชั้น 2: refreshSet — ไม่พับ details ของ GH ===
// L1953-1954 ใน parts.forEach(function(c){...})
var _oe=c.querySelector('.i-opts'); var _det=_oe?_oe.closest('details'):null;
if(_det){
  // *** แก้: GH = เปิด, อื่น = ปิด ***
  _det.open = isGH ? true : false;
  var _sm=_det.querySelector('summary');
  if(_sm && !_sm.dataset.ghSm){
    _sm.dataset.ghSm='1';
    _sm.textContent = isGH
      ? '⚙ ตัวเลือกเพิ่มเติม (มือจับ / มุ้ง / คาดตาราง / อื่นๆ)'
      : '⚙ ตัวเลือกเพิ่มเติม (มือจับ/ล็อค/มุ้ง/ครอบวงกบ — กดถ้าต้องใช้)';
  }
}
จุดต้องเคาะกับพี่นัท ก่อน dev แก้ (กระทบทั้ง G1 ด้วย!)
  • collapseOthers() ถูกใช้ทุกกลุ่ม (G1-G6) — แก้แบบ guard isGH ปลอดภัยสำหรับ G1 (G1 ไม่มี .gh-set-color-row) แต่ควรเคาะพี่นัทว่า: "ก็ยังต้องการให้ G1 พับแบบเดิมไหม?" → ถ้าใช่ guard แค่ GH ก็พอ
  • "ออปชั่นสำคัญ inline" — "ชนิดการเปิด" + "ราง" อยู่ใน opts อยู่แล้ว (.gh-opt-cat-det หมวด 🚪) ถ้าจะดันขึ้นฟอร์มหลักต้อง: (a) เพิ่ม HTML ใหม่ในฟอร์ม หรือ (b) move node ออกจาก opts ขึ้นมา → กระทบ readItem? ต้องตรวจก่อน ไม่แนะนำแก้ในรอบนี้ถ้าไม่แน่ใจ
  • ทางเลือกปลอดภัยกว่า: แก้แค่ชั้น 1+2 (ไม่พับการ์ด GH + details GH เปิด) แล้วประเมินผลก่อนทำ inline

UX อื่นๆ ที่ควรปรับ (ไม่ใช่ bug — ขัดหลักเรียบง่าย)

จุดสถานะเสนอแก้ผลกระทบ
summary "⚙ อุปกรณ์เสริม" text ยาวเกิน เสริม เปลี่ยนเป็น "⚙ ตัวเลือกเพิ่มเติม (มือจับ / มุ้ง / คาดตาราง / อื่นๆ)" — สั้น ชัด ครอบคลุม เฉพาะ GH
ปุ่ม "+ เพิ่มบาน" / "+ เพิ่มหลังคา" อยู่หลัง gh-master color row เสริม ย้ายปุ่มขึ้นก่อน gh-master (อยู่หัวชุด) — ผู้ใช้ไม่ต้องเลื่อนผ่านกล่องสีก่อน เฉพาะ GH · ดูดราฟ
ชุดล็อค (มีกุญแจ/ไม่มีกุญแจ) อยู่ใน opts ชั้นลึก เสริม ดันขึ้นฟอร์มหลักเฉพาะชนิดที่เป็น "ประตู" (เหมือนดราฟ) — แต่ต้องตรวจ readItem ก่อน กระทบ G1 ด้วย — เคาะพี่นัท
hint "เปลี่ยนที่นี่ = sync…" ใน global row OK hint ชัดพอ แต่ font เล็กมาก (11px) — ลอง 12px ขยับได้ตามใจ ทุกกลุ่ม
badge ชุด (ชุด 1/2/3) สีแดงทึบ OK คงเดิมได้ · ถ้าต้องการแยก GH ออกให้ชัด ลองชุดสี outline-red แทน solid Visual เล็กน้อย

ตรวจ colorOpts() / glassOpts() — มีรายชื่อซ้ำไหม

สี 13 ตัวเลือก / กระจก 66 ตัวเลือก → ใช้ dropdown (ถูกต้อง เกิน 6 ตัว) ไม่เปลี่ยนเป็นชิป

ผลตรวจ: ไม่พบซ้ำในรายชื่อตัวเลือก — ทั้ง colorOpts() และ glassOpts() generate จาก array COLORS/GLASSES ที่ไม่ซ้ำ · ปัญหาที่เห็น "ค่าเดิมโชว์ 2 ที่" เกิดจาก sync พฤติกรรม ไม่ใช่ข้อมูลซ้ำ
