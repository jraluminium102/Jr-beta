1. บั๊กที่ยืนยันจากโค้ด (ต้องแก้ทุกตัว)

บั๊ก A — "ซ่อนราง" โผล่ 2 รอบ (ซ้ำ)

สาเหตุ: COMMON_OPTS (บ.927) มี hide_track id รวม folding → render เป็น checkbox ที่บ.2685
พร้อมกันนั้น บ.2557-2559 มี o-track dropdown "โชว์ราง / ซ่อนราง (+5,000)" แสดงเฉพาะบานเลื่อนรางบน (_isTop)
แต่ folding ไม่ผ่าน block if(['บานเลื่อน','เลื่อนภายใน'].includes(p.cat)) → dropdown o-track ไม่ render สำหรับ folding
ดังนั้นที่เห็นซ้ำจริงคือ COMMON_OPTS render hide_track checkbox ครั้งแรก แล้ว groupGHOpts จัดหมวดแล้วทำซ้ำอีกครั้ง
หรือ (ตรวจสอบในเบราว์เซอร์จริง): อาจมี keyword "ซ่อนราง" ใน 2 bucket ของ CATS (บ.1782-1784 และ 1776) → node ถูก append 2 ครั้ง

โค้ดอ้างอิง: COMMON_OPTS บ.927 · render loop บ.2685 · groupGHOpts บ.1767

บั๊ก B — "รางยู" ซ้ำ 2 ที่
ตัวclass / idlabel ที่เห็นบรรทัดคิดเงินที่ไหน
u_track o-u_track checkbox รางยู +5,000 927 (COMMON_OPTS) · 2685 (render) บ.1456 opt += o.price flat 5,000
o-uchannel o-uchannel checkbox ฝังรางยู (ในพื้น) 2807 (render ทุก cat ยกเว้น excluded list) — folding ไม่อยู่ใน excluded → แสดง บ.1476-1479 opt += 1000 (ธรณีหลังเต่า บานเปิด เท่านั้น) — folding ไม่มีผลทางการเงินจาก uchannel โดยตรง

สองตัวนี้เป็นคนละสิ่ง: u_track = ราง U-profile ที่ฝังผนัง/เพดาน (ฟีเจอร์บานเฟี้ยมแบบซ่อน) · o-uchannel = ฝังธรณีรางยูในพื้น (บานเปิด/บานเลื่อน)

บั๊ก C — "เสริมคาน" หมวดผิด + ไม่มีช่องความยาว/รุ่น

หมวดผิด: groupGHOpts (บ.1790-1793) หมวด "มือจับ/ล็อค" มี keyword 'เสริมคาน' → o-beam checkbox label "เสริมคาน (เหล็กกล่อง)" ถูก bucket เข้าหมวดนี้
UI ขาดช่องความยาว/รุ่น: folding ใช้ p.optBeam → render checkbox o-beam (บ.2539) เท่านั้น ไม่มีช่อง dropdown รุ่น + ความยาว (ม.) แบบที่บานเลื่อน/เปิด/PC Door มี ผ่าน o-beamm + o-beammlen (บ.2595)
ผลต่อราคา: calc บ.1453 ใช้ RATES.BEAM × พื้นที่ (min 4,000) — ราคาคิดตามพื้นที่ แต่ UI เป็นแค่ checkbox ไม่มีช่องรุ่น/ยาวให้เซลล์ระบุ

โค้ดอ้างอิง: optBeam flag บ.600 · render บ.2539 · calc บ.1453 · o-beamm บ.2595

2. ตารางออปชั่นบานเฟี้ยม — เก็บ/ตัด/รวม

ออปชั่น (code id) หมวดปัจจุบัน หมวดที่ควรอยู่ ราคา / วิธีคิด สถานะ หมายเหตุ
ธรณี (o-threshf) ชนิด/การเปิด ชนิด/การเปิด (คงที่) display only · ไม่คิดเงิน เก็บ บ.2467-2468 · ถูกที่แล้ว
ซ่อนคาน (hide_beam) ชนิด/การเปิด (ผ่าน COMMON_OPTS) ชนิด/การเปิด flat 5,000 เก็บ ราคา flat เหมาะสมหรือไม่ — ดูข้อ 4
ซ่อนราง (hide_track) ชนิด/การเปิด (COMMON_OPTS) ชนิด/การเปิด flat 5,000 เก็บ แก้ซ้ำ แก้บั๊ก A ก่อน · ราคา flat ดูข้อ 4
รางยู (u_track) ชนิด/การเปิด (COMMON_OPTS) ชนิด/การเปิด flat 5,000 เก็บ ตัดคู่ เก็บตัวนี้ ตัด o-uchannel ออกจาก folding (ดูข้อ 2b)
ฝังรางยู (ในพื้น) (o-uchannel) อื่นๆ — calc: บวกเงินเฉพาะ บานเปิด+ธรณีหลังเต่า เท่านั้น · folding ไม่มีผลทางการเงิน ตัดออก ซ้ำกับ u_track · แก้บ.2806 เพิ่ม 'บานเฟี้ยม' ใน excluded list
เสริมคาน (o-beam) มือจับ/ล็อค (ผิด) โครงสร้าง/งานพิเศษ (ใหม่) area×RATES.BEAM min 4,000 (ปัจจุบัน)
เสนอ: upgrade เป็น รุ่น×ความยาว (ดูข้อ 3)		 ย้ายหมวด + upgrade UI ย้ายออกจากหมวด "มือจับ/ล็อค" · แก้ keyword groupGHOpts บ.1790-1793
มุ้ง (o-mosq) มุ้ง มุ้ง (คงที่) ตามเรตมุ้ง เก็บ ถูกที่แล้ว · p.mosquito=1
คาดตาราง (o-gridmark) คาดตาราง คาดตาราง (คงที่) เส้นนอน/ตั้ง × ม. × เรต เก็บ ถูกที่แล้ว
แผ่นทึบล่าง (o-solidlower) อื่นๆ โครงสร้าง/งานพิเศษ 3,500 หรือ 3,300 × ตร.ม. เก็บ p.cat 'บานเฟี้ยม' อยู่ใน _isPaneCat บ.2812
ครอบวงกบ (o-fcsides) อื่นๆ อื่นๆ (คงที่) ม. × เรตสี เก็บ ถูกที่แล้ว
ดรอปพื้น (o-dfm) อื่นๆ อื่นๆ (คงที่) 5,000 + (เกิน7ม.×750) เก็บ ถูกที่แล้ว
ฝังรางยู (ในพื้น) อีกครั้ง อื่นๆ — ดูด้านบน ตัดออก ซ้ำกับ u_track

3. เสริมคาน — ข้อเสนอ UX + คำถามให้พี่นัทเคาะ

สถานะปัจจุบัน (ข้อเท็จจริงจากโค้ด)
  • UI: checkbox เดียว label "เสริมคาน (เหล็กกล่อง)" — ไม่มีช่องรุ่น ไม่มีช่องความยาว
  • Calc: บ.1453 opt += Math.max(4000, area × rateOf(area, RATES.BEAM))
    RATES.BEAM = [[3.5,8,1300],[8,10,1100],[10,12,900],[12,∞,800]] บาท/ตร.ม.
    ตัวอย่าง: พื้นที่ 4 ตร.ม. → 4×1300 = 5,200 บาท · พื้นที่ 10 ตร.ม. → 10×900 = 9,000 บาท
  • ต่างจากบานอื่น: บานเลื่อน/เปิด/PC Door มี o-beamm dropdown เลือกรุ่น (2,400/3,600/4,400 ต่อ ม.) + ช่องกรอกความยาว (ม.) — เซลล์ระบุเองได้ชัดเจนกว่า

ข้อเสนอ: ควรเพิ่มช่องรุ่น + ความยาว (ม.) ให้ folding ด้วยไหม?

ทางเลือก A — คง checkbox เดิม (ราคา × พื้นที่ auto)

ข้อดี: กดน้อย · เซลล์ไม่ต้องรู้ความยาวคาน · เหมาะกับงานมาตรฐาน

ข้อเสีย: ราคาไม่ตรงงานจริงถ้าความยาวคานกับพื้นที่ไม่สัมพันธ์กัน · เซลล์ไม่รู้ว่าราคาคิดจากอะไร · ใบเสนอราคาระบุรุ่นไม่ได้

แก้เล็กน้อยได้: เพิ่ม hint "ราคา auto จากพื้นที่" ใต้ checkbox เพื่อให้เซลล์เข้าใจ

ทางเลือก B — upgrade เป็น chip รุ่น + ช่องความยาว (แบบเดียวกับ o-beamm)

ข้อดี: ราคาตรงความเป็นจริง · เซลล์คุมราคาได้ · ใบเสนอราคาระบุรุ่น+ความยาวได้ชัด · pattern เดียวกับบานอื่น = ไม่งง

ข้อเสีย: กรอกเพิ่ม 2 ช่อง (รุ่น + ความยาว) · ต้องแก้ calc ด้วย (ตัด p.optBeam branch · เพิ่ม folding เข้า o-beamm block บ.2595 + readItem บ.2923)

โค้ดที่ต้องแก้: บ.2595 เพิ่ม 'บานเฟี้ยม' ใน cat list · บ.2923 เพิ่ม 'บานเฟี้ยม' ใน readItem · ตัด p.optBeam check บ.1453 สำหรับ folding

คำถามให้พี่นัทเคาะ (เรื่องราคา — UX ไม่ตัดสิน)
  1. บานเฟี้ยมงานจริง — เสริมคานมักจะยาวเท่าไร? ตรงกับความกว้างบาน หรือแตกต่างกัน?
  2. ใช้คานรุ่นเดียวกับบานเลื่อน (2,400 / 3,600 / 4,400 ต่อ ม.) หรือรุ่นพิเศษ?
  3. เซลล์ต้องการระบุรุ่นคานในใบเสนอราคาบานเฟี้ยมไหม?

ถ้าพี่นัทเลือก B: dev แก้บ.2595 + บ.2923 + ลบ p.optBeam branch สำหรับ folding ออก

4. ซ่อนคาน / รางยู / ซ่อนราง — flat 5,000 vs ×ความยาว

ปัจจุบันทั้ง 3 ตัวคิด flat 5,000 บาท (บ.1456 opt += o.price)

ออปชั่น ข้อดี flat 5,000 ข้อดี ×ความยาว (ม.)
ซ่อนคาน
(hide_beam)
  • กดเดียวจบ ไม่ต้องกรอกความยาว
  • งานขนาดมาตรฐานราคาใกล้เคียงกัน
  • เซลล์ไม่ต้องวัดความยาวคาน
  • งานกว้าง (เช่น 5-6 ม.) flat 5,000 ถูกเกิน
  • ราคาสะท้อนต้นทุนวัสดุ+แรงงานจริง
  • ใบเสนอราคาโปร่งใสขึ้น
ซ่อนราง
(hide_track)
  • เหมือนกันกับซ่อนคาน
  • งานส่วนใหญ่รางไม่ยาวมาก
  • รางยาวหลายเมตร flat ขาดทุน
  • ตรง pattern หลังคา (ซ่อนสโลป ×ม.)
รางยู
(u_track)
  • เหมือนกัน
  • งาน folding ส่วนใหญ่รางยูสั้น
  • folding กว้าง 4-5 ม. flat ถูกเกิน
  • รางยูฝังพื้นยาวตามบาน
คำถามให้พี่นัทเคาะ (เรื่องราคา — UX ไม่ตัดสิน)
  1. ซ่อนคาน/ซ่อนราง/รางยู ของบานเฟี้ยม — งานจริงราคาต่างกันมากไหมตามความยาว?
  2. ถ้าคิด ×ม.: เรตควรเป็นเท่าไร (เช่น 1,000/ม. · 1,500/ม.) และมี minimum ไหม?
  3. หรือพอใจ flat 5,000 ต่อไปเพราะงานเฟี้ยมส่วนใหญ่ขนาดใกล้เคียงกัน?

ถ้าพี่นัทเปลี่ยนเป็น ×ม.: dev ต้องแก้ COMMON_OPTS เพิ่ม field perLength:true + เพิ่มช่องกรอกความยาวให้แต่ละตัว + แก้ calc บ.1456
