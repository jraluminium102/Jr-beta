## 🔴 ปัญหาปัจจุบัน
ตัวอ่านออปชั่น→`optSel` (ก้อนที่ส่งเข้า `calcUnit`) **เขียนซ้ำ 3–4 ที่ แยกกัน:**
| ที่ | ฟังก์ชัน | บรรทัด≈ | ใช้กับ |
|---|---|---|---|
| 1 | `readItem` | L5120 (optSel L5144) | โหมดใบเสนอ (เต็ม) ทุกกลุ่ม |
| 2 | `qiCalcG1`–`qiCalcG7` | L2153+ (dispatch L2158-2163) | โหมดคิดเร็ว แยก 7 ฟังก์ชัน |
| 3 | `g6rOptSel` | L6977 | กลุ่ม 6 ห้อง |
| 4 | `calcSubItemPrice` | L4438 | บานผสม (ฮาร์ดโค้ด fixed_glass) |

→ เพิ่มออปชั่น = ต้องต่อสายให้ครบทุกที่ · ลืม = โหมด/กลุ่มนั้นเพี้ยน

## ✅ สิ่งที่จะทำ
1. สร้างฟังก์ชันกลาง **`buildOptSel(src)`** = รับ object ออปชั่นมาตรฐาน → คืน `optSel` (ตรรกะ map เดียว)
2. แต่ละตัวอ่าน (readItem / qiCalcG_ / g6rOptSel) เหลือหน้าที่แค่ **ดึงค่าจาก DOM/state → ทำ object มาตรฐาน → เรียก `buildOptSel`** (ไม่ map optSel เองอีก)
3. ไม่แตะ `calcUnit` · ไม่แตะสูตร · ไม่แตะการแสดงผล (วาดฟอร์มไว้เฟสหลัง)

## 🛡️ วิธีทำแบบไม่พัง (สำคัญ)
- **เฟส 0 ก่อน:** ขยาย `golden-snapshot.mjs` ให้ครอบ **2 โหมด × 7 กลุ่ม × G6 ห้อง × บานผสม** (ตอนนี้ 149 เคสเน้นโหมดเต็ม → คิดเร็ว/G6 ยังไม่ถูกคุ้ม = พังเงียบได้)
- **ทำทีละตัวอ่าน** (ไม่รวดเดียว): readItem ก่อน → golden 0 เพี้ยน → qiCalcG_ ทีละกลุ่ม → golden → g6rOptSel → golden
- ทุกขั้น `node scripts/golden-snapshot.mjs` **ก่อน-หลัง ต้อง 0 เพี้ยน** · เพี้ยนเมื่อไหร่ = map ไม่ตรง revert ทันที
- เทสเบราว์เซอร์จริงทั้ง 2 โหมด + G6 หลังแต่ละกลุ่ม

## ⚠️ จุดเสี่ยง/ต้องระวัง
- ชื่อ key ใน optSel ของ 3 ตัวอ่านอาจ **ไม่ตรงกันอยู่เดิม** (เช่น คิดเร็วใช้ `d.dataset.qiG4color` · เต็มใช้ `.o-ftcolor`) → ต้อง map ให้ตรง key ที่ `calcUnit` อ่านจริง ก่อนรวม
- `calcSubItemPrice` ฮาร์ดโค้ด fixed_glass — **เฟสนี้ยังไม่แตะ** (เป็นงานแยก "บานผสมคิดตามชนิด") กันขอบเขตบาน
- กลุ่ม 6 ซ่อนฟอร์มด้วย CSS `.g6room` → ระวัง side-effect (บทเรียน verify-g6-on-layout-change)
