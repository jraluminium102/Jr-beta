# ตรวจสูตรค่าสี + ราคาขาย R4.1 (คิดราคา 4.0) — นักบัญชี 13 ต.ค.69
สถานะ: **ผ่านแบบมีเงื่อนไข.** สูตรในเอนจินคิดเลขถูก แต่ข้อมูลหน้าเทียบมี 3 จุดที่จะทำให้เจ้าของอ่านเลขผิด และ % แยกขนาดมีความเสี่ยงขายขาดทุน 1 จุด

## พบข้อผิดพลาด / ความเสี่ยง (เรียงตามความรุนแรง)
1. **ระแนงหมุน % ค่าของ = −1% (ขายของต่ำกว่าทุน).** pricebook `matPctBySize.louver_rotate._ = [[3,−1],[4.8,27],[7.8,47]]` แปลว่าพื้นที่ ≤3 ตร.ม. จะขายค่าของ 99% ของทุน ที่ยังรอดได้เพราะมอเตอร์ขายฟิก 12,000 (ทุนประมาณ 1,800) มาช่วยไว้
   - คิดมือ 150×200: ทุนของไม่รวมมอเตอร์ ≈8,743 → 8,743×0.99 + 3,430 + 7,177 = 19,262.6 → ปัดเป็น 19,300 แล้วบวกมอเตอร์ 12,000 = 31,300 ตรงกับเว็บ
   - **ถ้าลูกค้าไม่เอามอเตอร์** (`spec.rnMotor==='ไม่เอา'`) ราคาจะเหลือ 19,300 ต่อทุนรวม 14,381 → กำไรสุทธิ = (19,300−4,453.8−14,381)÷19,300 = **2.4%** ทั้งที่เป้าคือ 26%
   - % ชุดนี้จูนมาจากแถวที่มีมอเตอร์ จึงใช้กับงานที่ไม่มีมอเตอร์ไม่ได้
2. **sellTM ใช้ค่าแรงขายของตาราง ไม่ใช่ค่าแรงขายที่เอนจินคิดจริง** (`gen-r41-compare-data.mjs:43` ใช้ `r.pdf.sP + r.pdf.sI`)
   - แถวที่ทุนค่าแรงเว็บไม่เท่าตาราง เอนจินจะคิดค่าแรงขาย = ทุน × ตัวคูณของแถวอ้างอิง (`engine.mjs:1272-1276`) ไม่ได้ใช้เลขตารางตรง ๆ
   - ตัวอย่าง หลังคาเลื่อน ไวนิล 400×200: ทุนผลิตเว็บ 4,410 เทียบตาราง 5,024 ทำให้ค่าแรงขายเว็บ 28,499 แต่ sellTM ใช้ 31,335 → sellTM สูงเกินของจริงที่เว็บจะคิด **≈2,800 บาท**
   - แถวระแนงบังตาก็เป็นแบบเดียวกัน (ทุนผลิตเว็บ 2,202 เทียบตาราง 2,111)
3. **ตัวคูณที่โชว์ 2 ตำแหน่ง ไม่ใช่ตัวที่ใช้คิดจริง** (สคริปต์ใช้ค่ามัธยฐานที่ไม่ปัด)
   - ตัวอย่าง SMS 250×240: 9,546×2.72 + 2,900 + 3,800 = 32,665.12 → ปัดได้ 32,700 แต่ช่อง sellTM ขึ้น **32,800** ถ้าเจ้าของคิดมือจะได้ไม่ตรง 100 บาท
   - อีกเรื่อง: tableMult ไม่ใช่ sM/cM ของแถวนั้น แต่เป็นค่ามัธยฐานของทั้งรุ่น/แบบย่อย (บรรทัด 36-41) และเลือกตัวกลางบนเมื่อจำนวนแถวเป็นคู่ ควรเขียนบอกไว้บนหน้า
4. **รุ่นที่มีมอเตอร์ขายฟิก (ประตูรั้ว/ระแนงหมุน): "% ค่าของ × ทุน" ไม่ได้ค่าของขาย**
   - `cost.total` รวมทุนมอเตอร์ไว้แล้ว (`engine.mjs:1149-1151`) แต่ % คูณเฉพาะ `costTotal` ที่ไม่รวมมอเตอร์ (`:975`)
   - ตัวอย่าง ระแนงหมุน: โชว์ −1% แต่ sM÷cM = 1.96
   - ต้องโชว์มอเตอร์แยกบรรทัด ไม่งั้นตรวจมือไม่ผ่าน
5. **% แยกขนาดกลายเป็นตัวเลขอุดช่องว่าง (plug) ไม่ใช่อัตรากำไรจริง:** ดูข้อ B

## A. ค่าอบสี: คิดอย่างไรจริง
- **กก.ที่เข้ากองอบ** = จำนวนเส้นที่ซื้อ (รวมเศษเผื่อ) × กก./เส้น (`kgForBake` :318 ใช้ `ALUWEIGHT_KGM`×ความยาวเส้นก่อน ถ้าไม่มีจึงใช้ `it.kg`)
  - เส้นจะเข้ากองเฉพาะเมื่อไม่มีราคาสีเลย ไม่มีตัวคูณสีกล่อง ไม่ใช่เส้นสีเงิน และไม่ใช่ colorIn ที่ข้ามได้ (:501)
  - น้ำหนักที่ใช้คิดราคาเส้น (`ALU_KG`) กับน้ำหนักที่ใช้คิดค่าอบมาจากคนละคีย์ สุ่ม B20054 แล้วตรงกัน (6.6 = 1.03125×6.4) แต่ควรมีด่านเทียบทุกรหัส
- **เรตค่าอบ** = `PB.BAKE[color]` คือ 0/100/173/190 ตรงกฎเจ้าของ (มีลายไม้สต็อก 112.5 ตามไฟล์ v20.1 B16 ด้วย)
  - เส้นที่แบรนด์ไม่มีสีนั้นขาย (`brandNoColor`) แยกไปอีกกอง เรต = max(พิเศษ 173 หรือลายไม้ 190, เรตสี) (:536-549)
- **เปิดตู้อบ 2,000** เมื่อเป็นสีพิเศษ/ลายไม้พิเศษ หรือมีเส้นที่แบรนด์ไม่มีสี หรือรุ่น ovenAlways/millBar-ขาว (:567) คิดครั้งเดียวต่องาน ตรงกฎเจ้าของ
- **คิดซ้ำ:** ไม่พบ
  - เส้นที่ได้ราคาสีจากแบรนด์/ไฟล์/สโตร์จะไม่เข้ากองอบ (:501)
  - colorIn ข้ามเฉพาะสีขาว/ดำ หรือ colorInAlways (:500)
  - สีพิเศษไม่มีคีย์ใน `ALU_COLOR_NAME` → ไม่มีราคาสีแบรนด์ จึงคิดเป็นขาว + 173×กก. ถูกต้อง
- **คิดขาด:** ไม่พบในเส้นทางปกติ จุดที่ต้องจับตามี 2 จุด
  - (ก) ลายไม้สต็อกที่ไม่มีราคาสี จะตกไปคิด ขาว + 112.5/กก. และขึ้นป้ายว่า "ค่าอบสี" ซึ่งขัดกับกฎ "ลายไม้สต็อกไม่อบ" แม้ตัวเลขเอามาจากไฟล์ ควรเปลี่ยนป้ายเป็น "ส่วนต่างสี" หรือให้เจ้าของยืนยัน
  - (ข) ราคาสีจากไฟล์/สโตร์ที่ไม่แพงกว่าขาว จะถูกข้าม (`okColor` :455) แล้วไปคิด ขาว + ค่าอบ ส่วนนี้ตั้งใจไว้ ไม่ใช่บั๊ก

## B. ราคาขาย R4.1 ในเอนจิน (`engine.mjs:963-982`)
- สูตร: matRaw = ทุน × (1+%) แล้ว ขายรวม = ปัดร้อย(matRaw + ค่าแรงขายผลิต + ค่าแรงขายติดตั้ง) **ปัดครั้งเดียว** ค่าของที่โชว์ = ยอดรวม − ค่าแรง 2 ก้อน (:1142) เศษปัดไปตกที่ค่าของ (<100 บาท) ถูกต้อง
- คิดมือ (ไม่มีมอเตอร์) ตรงทุกแถว:
  - SMS 250×240: 9,546×2.62 = 25,010.5 + 6,700 → 31,800 ✓ (ค่าของ 25,100 = 25,010.5 + เศษ 89.5)
  - SMS 400×280: 13,650×2.62 + 7,860 = 43,623 → 43,700 ✓
  - Velora 80×200: 7,581×1.87 + 4,748 = 18,924.5 → 19,000 ✓
- matPctBySize ไล่ค่าเส้นตรงแล้วปัดเป็น % เต็ม (:1281-1305) ตัวสูตรถูก แต่จุดในตารางทำให้ราคาส่วนเพิ่มแกว่ง:
  - ประตูรั้ว ระแนงสลับ [10→130%, 12→194%]: ที่ 10 ตร.ม. ค่าของขาย ≈39,206×2.30 = 90,174 ที่ 12 ตร.ม. ≈42,422×2.94 = 124,721 → **ราคาค่าของ +38% ขณะที่พื้นที่เพิ่มแค่ 20%**
  - ประตูรั้ว ระแนง [6→149, 8→119, 10→132]: ช่วง 6→8 ตร.ม. ทุนเพิ่ม ~4,983 แต่ค่าของขายเพิ่มแค่ ~1,800 (ส่วนที่เพิ่มขายต่ำกว่าทุน) แล้วช่วง 8→10 ราคากลับพุ่ง
  - บานเลื่อนรางบน 1 บาน = 38% แต่ 2 บาน ≤6 ตร.ม. = 83% (กระโดด 45 จุดที่ขนาดเท่ากัน)
  - ต้นเหตุคือทุนเว็บไม่เท่าตาราง (เช่น ระแนงสลับ 600×220: ทุนเว็บ 44,351 เทียบตาราง 51,267) แล้วเอา % ไปอุดส่วนต่าง

## C. sellTM + กำไรสุทธิในหน้าเทียบ
- `netOf` (template :259) = (ขาย − ขาย×30/130 − ทุนรวม) ÷ ขาย **ตรงนิยามเจ้าของ**
  - ทุนรวม = cost.total (รวมทุนมอเตอร์) + ทุนค่าแรง 2 ก้อน ใช้คู่กับยอดขายที่รวมมอเตอร์ขาย ถือว่าสอดคล้องกัน
- คิดมือเทียบ:

| แถว | sellTM | สูตร sellTM | กำไรสุทธิ sellTM | ตาราง | เว็บตอนนี้ |
|---|---|---|---|---|---|
| SMS 250×240 | 32,800 | อยู่ในช่วงที่ตัวคูณจริง 2.7237–2.7341 ✓ | (32,800−7,569.2−11,997)÷32,800 = 40.3% | 40.3% | 39.2% |
| SMS 400×280 | 45,100 | — | 40.4% | 40.3% | 39.2% |
| Velora 80×200 | 23,000 | — | 35.7% | 35.7% | — |
| รางบน 90×220 1 บาน | 27,300 | — | 30.9% | — | 15.7% (ขายตอนนี้ 20,500) |

- สรุป: ใช้ตัวคูณของตารางแล้วกำไรสุทธิกลับมาเท่าตารางทุกแถวที่ตรวจ แต่ต้องแก้ข้อ 2 และ 3 ก่อนส่งให้เจ้าของ

## D. ข้อเสนอ: ตัวคูณค่าของเท่าตาราง R4.1
- **เก็บแบบ:** % เดียวต่อรุ่น × แบบย่อย (vk) = มัธยฐาน sM/cM ของตาราง − 1 (เช่น SMS ≈172%, รางบน ≈108%, Velora ≈140%) เป็นจำนวนเต็มให้เลขที่โชว์ = เลขที่คิด
  - แยกตามจำนวนบานเฉพาะกรณีที่ตารางต่างกันจริง และ**เลิกใช้ matPctBySize**
  - รุ่นที่มีมอเตอร์ให้หักมอเตอร์ออกทั้งฝั่งทุนและฝั่งขายก่อนหาตัวคูณ
  - ตัวคูณจากตารางมีเศษปัดร้อยติดมาด้วย (+0.3–2.5% ในงานเล็ก) ควรหัก ~50 บาทก่อนหาร
- **ผลในมุมบัญชี:**
  - ได้อัตรากำไรขั้นต้นของค่าของคงที่ ตรวจย้อนได้ (% × ทุน = ขาย) ไม่มีการโยกกำไรข้ามขนาด และไม่มีกรณีขายต่ำทุนแบบข้อ 1
  - ข้อแลก: ยอดรวมจะห่างจากตารางเท่ากับ (ทุนเว็บ − ทุนตาราง) × ตัวคูณ เช่น Velora +20%, รางบน 1 บาน +33%, หลังคาเลื่อน −13%, ระแนงสลับ 600×220 −10%
  - ส่วนต่างพวกนี้คือ**ทุนที่ไม่ตรงกัน** ต้องแก้ที่ต้นทุน (ราคาเส้นสโตร์ Velora/สูตรวัสดุ) ไม่ใช่ซ่อนไว้ใน %
  - เทียบกับวิธีปัจจุบัน (จูน % ตามขนาด): ยอดรวมชนตาราง ±3% แต่ % ไม่มีความหมายทางบัญชี และต้องจูนใหม่ทุกครั้งที่ราคาอลูเปลี่ยน
- **ต้องให้เจ้าของเคาะ:**
  - รับได้ไหมที่ยอดรวมจะห่างจากตาราง (ตามทุนจริง)
  - ระแนงหมุนไม่เอามอเตอร์ จะตั้งพื้น % ค่าของขั้นต่ำเท่าไร
