## หลักการ
ต่อยอดปุ่ม **"แยกราคาแต่ละส่วน"** เดิม (`toggleSplit` L6252 · ตอนนี้แยกแค่ระดับ "ชุด") → เพิ่มระดับ **"ส่วนประกอบในแต่ละรายการ"**

## 1. Engine: expose ค่าย่อยที่คิดอยู่แล้ว (ไม่แตะสูตร)
`calcUnit` มีตัวแปรแยกอยู่แล้ว (L1806 `const extras=glassUp+colorUp+opt`) → เพิ่มใน return เป็น `priceLines`:
```
priceLines: [
  {label:'ตัวบาน + [กระจกฐาน]', amount: base},
  {label:'อัพเกรดกระจก [ชื่อ]', amount: glassUp},   // ถ้า >0
  {label:'สีอบ [ชื่อสี]', amount: colorUp},          // ถ้า >0
  ...addonLines (มุ้ง/ออปชั่น ที่มี .p อยู่แล้ว),
  ...OPTION ทางเลือกลูกค้า (oc · มี ±บาท อยู่แล้ว)
]
```
- **base/glassUp/colorUp = แยกตรงๆ** (มีตัวแปรแล้ว) · **opt** = แตกจาก addonLines + msgs ที่มีตัวเลข (มุ้ง L1896 มี .p แล้ว · อื่นๆ เก็บ {label,amount} ตอน push)
- **G3** ใช้ `g3box` (roofend/extras/slide/ceil · structured แล้ว) → map เป็น priceLines ได้เลย
- ⚠ **ผลรวม priceLines ต้อง = sell เป๊ะ** (assert ตอนเทส · ไม่งั้นเลขไม่ตรง)

## 2. UI: โหมด "แสดงราคาย่อย"
- ปุ่มบนหัวใบ (ต่อจาก splitBtn): รวมราคา (default) ↔ **แสดงราคาย่อย**
- กดแล้ว แต่ละรายการกางบรรทัดย่อย (ตาม priceLines) · indent + ราคาขวา · ส่วนเพิ่มขึ้น "+" สีเขียว (ดูดราฟ)
- **G6 = 2 ชั้น**: ชุด (qSplit เดิม แยกแต่ละด้าน) → + ส่วนประกอบในแต่ละด้าน
- พิมพ์/PDF ได้ทั้ง 2 โหมด

## 3. Default + ความสะอาด
- **default = รวมราคา** (ใบสะอาดเหมือนเดิม · ลูกค้าทั่วไป) · กด "แสดงราคาย่อย" เฉพาะตอนลูกค้าอยากเห็น
- ราคาย่อย = เลขจริงจาก engine (ไม่ปัด/ไม่แต่ง) · ผลรวม = ยอดรายการเป๊ะ
