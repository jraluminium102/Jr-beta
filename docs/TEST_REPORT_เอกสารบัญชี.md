## 4. ใบวางบิล / งวด / ใบเสร็จ — 🔴→**แก้แล้ว** 2 จุด

### 4.2 🔴 บั๊ก: จ่ายงวดบางส่วน → งวดเด้งเป็น "paid" → **แก้แล้ว**
- เดิม: `pay` route ตั้ง `status:"paid"` เสมอ ไม่ว่าจ่ายเท่าไร
- **แก้แล้ว**: ดึง `amount` ของงวดมาเทียบ — จ่ายครบ=`paid`, จ่ายไม่ครบ=`pending` (enum `installment_status` มีแค่ pending/paid — **ไม่แตะ structure DB**; สถานะ "partial" อยู่ที่ระดับใบวางบิลซึ่งคำนวณถูกอยู่แล้ว) + ยืนยันงวดอยู่ในใบนี้จริง (กัน update เงียบ → 404)

### 4.3 🔴 บั๊ก: ใบเสร็จคิด VAT ซ้อน → **แก้แล้ว (รอยืนยันความหมายธุรกิจ)**
- เดิม: ยอดงวด = `quotation.net` (รวม VAT แล้ว) แต่ฟอร์มใบเสร็จเอายอดนี้ใส่ช่อง "ยอดก่อน VAT" แล้วบวก 7% อีก → VAT ซ้อน + ฐานภาษีผิด
- **แก้แล้ว**: ฟอร์มใบเสร็จถอด VAT ออกจากยอดงวดก่อน (`ยอดก่อน VAT = ยอดงวด / 1.07`) → ยอดสุทธิใบเสร็จ ≈ ยอดงวดที่ลูกค้าจ่าย
- **รอปรึกษาบัญชี (พี่นัทแจ้ง)**: ยังไม่ฟันธงว่า `quotation.net` รวม VAT แล้วจริงไหม + บางงานลูกค้าไม่เอา VAT (vat_rate=0) → **คงไว้แค่การถอด VAT เมื่อ VAT>0 เท่านั้น** (กรณี 0% ระบบไม่ถอด/ไม่บวก VAT อยู่แล้ว ถูกต้อง) จะไม่แก้ logic เพิ่มจนกว่าบัญชียืนยัน · กรณีมี WHT ต้องตรวจเคสจริง

### 4.4 🟡 ข้อเสนอแนะ
- กันออกใบเสร็จเกินยอด/ซ้ำงวดเดิม (ตอนนี้ยังออกได้ไม่จำกัด) · ผูก "รับชำระ (pay)" กับ "ออกใบเสร็จ" ให้เป็น flow เดียว (ตอนนี้แยกกัน อาจลืมออกใบเสร็จ)
