## ข่าวดีก่อน: engine คิดราคา "มีที่เดียวอยู่แล้ว" ✅

**`calcUnit(p, w, h, gi, ci, panels, optSel, shipOnly)` (L1296)** = สูตรคิดราคาต่อหน่วยตัวจริง **ตัวเดียว** · ทุกอย่างเรียกตัวนี้หมด:
- โหมดใบเสนอ (เต็ม) → `calcQuote` (L5444) → `readItem` (L5120) → `calcUnit` (L5352)
- โหมดคิดเร็ว → `calcQuickAll` (L2153) → `qiCalcG1..G7` → `calcUnit`
- กลุ่ม 6 ห้อง → `g6rPrice`/`roofTotalReal` (L7061/6961) → `calcUnit`
- บานผสม (subitem) → `calcSubItemPrice` (L4438) → `calcUnit`

➡️ **เป้าหมาย "สูตรอยู่ที่เดียว" บรรลุไปแล้วระดับนึง** — แกนคิดเงินไม่ได้ก็อปซ้ำ 7 กลุ่ม

## ❓ Q1 — สูตรแต่ละกลุ่มเขียนซ้ำกี่ที่?

| ชั้น | ซ้ำกี่ที่ | รายละเอียด |
|---|---|---|
| **แกนคิดเงิน (calcUnit)** | **1 ที่** ✅ | แต่เป็นฟังก์ชันยักษ์ รวม if ทุกกลุ่ม/ชนิดไว้ในตัวเดียว (per_sqm/bucket/ต่อบาน/หลังคา/ตู้/มุ้ง/ม่านซิป) |
| **ตัวอ่านออปชั่น→optSel** | **🔴 3 ชั้น (ซ้ำ)** | `readItem` (เต็ม · ทุกกลุ่มรวมกัน L5144) · `qiCalcG1–G7` (คิดเร็ว · **7 ฟังก์ชันแยกกลุ่ม** L2158-2163) · `g6rOptSel` (G6 ห้อง L6977) |
| **บานผสม** | แยกอีก 1 | `calcSubItemPrice` (L4438) — เรียก calcUnit แต่ **ฮาร์ดโค้ด `fixed_glass` + optSel ว่าง** (ไม่ส่งออปชั่น/ชนิดจริง) |

➡️ **สูตรแกนไม่ซ้ำ แต่ "วิธีป้อนออปชั่นเข้าสูตร" ซ้ำ 3–4 ชั้น** — นี่คือตัวปัญหา

## ❓ Q2 — 2 โหมดใช้ logic ก้อนเดียวกันไหม?

- **แกนคิดเงิน (calcUnit): ใช่ ก้อนเดียวกัน** ✅
- **ตัวอ่านค่า + การแสดงผล: ❌ แยกคนละชุด (ก็อป)**
  - เต็ม: `readItem` (อ่านค่า) + `buildItemOpts` (วาดฟอร์ม L4217) + `genQuote` (ออกใบ) · ใช้ `.i-*`
  - เร็ว: `qiCalcG1–G7` (อ่าน+คิด) + `qiDispatch`/`qiRebuild` (วาดฟอร์ม) + `genQuoteQuick` · ใช้ `.qi-*`

➡️ **คิดเงินใช้ร่วม · แต่ "อ่านออปชั่น + วาดจอ" ทำ 2 ชุดคู่ขนาน** → เพิ่ม/แก้ออปชั่น 1 ตัว ต้องไปแก้ทั้ง readItem **และ** qiCalcG_ ของกลุ่มนั้น · ลืมชุดใด = โหมดนั้นคิดผิด/ไม่โชว์ = อาการ **"แก้โหมดนึง อีกโหมดพัง / แก้ผิดโหมด"**

## ❓ Q3 — จุดที่โค้ดพันกันจนแก้แล้วลามพัง

1. **🔴 optSel 3 ชั้น (ใหญ่สุด)** — ออปชั่นเดียว (เช่น แผ่นทึบล่าง/ธรณี/มุ้ง) ต้องไปต่อสายใน `readItem` + `qiCalcG_` + `g6rOptSel` ให้ครบ · พลาดที่ใดที่นึง = กลุ่ม/โหมดนั้นเพี้ยน
2. **🔴 `buildItemOpts` (L4217 · ~600 บรรทัด) = วาด UI + ย้าย DOM + hack ปนกัน** — ย้ายมือจับ/สี/กระจก/prodsel ออกนอก `.i-opts` + dedup (บั๊กมือจับซ้ำมาจากตรงนี้) · **กลุ่ม 6 ซ่อนฟอร์มด้วย CSS `.g6room` ครอบ** → ขยับ DOM ตรงนี้ทีไรเสี่ยงพัง G6 (บทเรียนเดิม [[verify-g6-on-layout-change]])
3. **🟡 G1↔G6 ชนิดบาน 2 แหล่งซ้อน** — `G1GROUPS` (mirror global L3649) + `G6GROUPS` (ใน IIFE L6538) ต้อง sync มือ ([[g1g6-door-catalog-unify]])
4. **🟡 `calcSubItemPrice` แยกตัว** — ไม่ผ่าน readItem/optSel ปกติ → บานผสมไม่รับออปชั่น/ชนิดจริง (ฮาร์ดโค้ด fixed_glass)
5. **🟡 calcUnit เป็น monolith** — แก้ branch กลุ่มนึงเสี่ยงกระทบตัวแปร/fall-through กลุ่มอื่นในฟังก์ชันเดียวกัน

## 🛠️ แผนรื้อ (แบบไม่พังของเดิม · มี golden เป็นตาข่าย)

**กฎ:** ทุกเฟส รัน `node scripts/golden-snapshot.mjs` ก่อน-หลัง → **ราคาเดิมต้อง 0 เพี้ยน** (refactor = ผลลัพธ์เท่าเดิม) · ทำทีละเฟส หยุดให้ตรวจ

### เฟส 0 — ขยายตาข่าย (ก่อนแตะอะไร)
- เพิ่มเคส golden ให้ครอบ **ทั้ง 2 โหมด × 7 กลุ่ม × G6 ห้อง × บานผสม** (ตอนนี้ golden 149 เคสเน้นเต็ม) — กันพังเงียบในโหมดคิดเร็ว/G6

### เฟส 1 — รวม "ตัวอ่านออปชั่น" เป็นที่เดียว (กำไรสูงสุด · เสี่ยงต่ำ)
- สร้าง **`buildOptSel(src)` ตัวเดียว** = รับ object ออปชั่นมาตรฐาน → คืน optSel ให้ calcUnit
- ให้ `readItem`, `qiCalcG1–G7`, `g6rOptSel` **เรียกตัวเดียวกันนี้** (แต่ละตัวแค่แปลง DOM/state → object มาตรฐาน แล้วส่งเข้า buildOptSel)
- ➡️ เพิ่มออปชั่นใหม่ = แก้ที่เดียว ทุกโหมด/กลุ่มได้พร้อมกัน · **จบอาการ "แก้โหมดนึงอีกโหมดพัง"**
- golden: output เท่าเดิมเป๊ะ

### เฟส 2 — แยก "ฟีเจอร์ไหนโชว์" เป็น config (data ไม่ใช่ code ก็อป)
- ทำตาราง **`FEATURE_MATRIX[group][mode]`** = กลุ่มนี้/โหมดนี้โชว์ control อะไร (มือจับ/มุ้ง/คาดตาราง/ธรณี/แผ่นทึบล่าง...)
- `buildItemOpts` (เต็ม) + `qiDispatch` (เร็ว) อ่านตารางเดียวกัน → โหมด = แค่ "เลือกโชว์" ตามที่พี่ตั้งเป้า
- ➡️ คิดเร็ว = subset ของเต็ม โดยอัตโนมัติ ไม่ต้องก็อป

### เฟส 3 — ลดการย้าย DOM ใน buildItemOpts
- ให้ฟอร์ม render ตำแหน่งถูกตั้งแต่แรก (ไม่ต้อง appendChild/relocate มือจับ/สีออกนอก .i-opts ภายหลัง) → ตัด dedup hack + เลิกเสี่ยงพัง G6
- golden + เทส G6 ของจริงทุกครั้ง

### เฟส 4 — แตก calcUnit + รวม GROUPS
- แยก branch กลุ่มใน calcUnit เป็นฟังก์ชันย่อยตั้งชื่อ (priceSlide/priceRoof/priceCabinet...) เรียกผ่าน dispatcher — คณิตเท่าเดิม blast radius เล็กลง
- รวม `G1GROUPS`+`G6GROUPS` เป็น global ตัวเดียว เลิก mirror

> ลำดับ: **0 → 1 → 2 → 3 → 4** · เฟส 1 ให้ผลคุ้มสุด-เสี่ยงน้อยสุด ควรทำก่อน · เฟส 3-4 ค่อยทำเมื่อ 1-2 นิ่ง
