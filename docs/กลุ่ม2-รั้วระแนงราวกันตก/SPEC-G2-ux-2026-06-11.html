3. มติ R4 — บานเปิด (override ราคาประตู)

ใช้ได้กับ: ระแนง (o-doortype + o-doorprice) และ ระแนงเลื่อน (o-bsdoor + o-bsdoorprice)

Before → After

เดิมใหม่
input ราคาประตู override ดูเหมือน field ธรรมดา · ไม่มีคำแนะนำขั้นต่ำ · จำนวนบาน = ไม่มีในฟอร์มนี้ กล่องสีส้มเด่น ประกอบด้วย:
1. input ราคา (กว้าง โดดเด่น)
2. stepper จำนวนบาน (1–4)
3. ราคา auto แสดงใต้ stepper: "auto: 18,000 บ." (คำนวณตามสูตรด้านล่าง)
4. คำแนะนำ: บานเดี่ยว ≥ 18,000 · บานที่ 2+ = 16,000/บาน
5. ข้อความเตือนแดง: "กรอก >0 = ใช้แทนราคาอัตโนมัติ"
สูตรราคาประตู auto (floor):
n=1: 18,000 บ.
n=2: 18,000 + 16,000 = 34,000 บ.
n=3: 18,000 + 32,000 = 50,000 บ.
n=4: 18,000 + 48,000 = 66,000 บ.
สูตร: 18,000 + (n-1) × 16,000 · ใช้วงกบร่วม บานที่ 2+ ถูกกว่า
Logic: ถ้ากรอก override > 0 → ใช้แทนราคาอัตโนมัติ (ไม่คำนวณเอง)
ถ้าว่าง/0 → ใช้ auto ตามสูตร
จุดโค้ด: ระแนง o-doorprice ≈ บรรทัด 2619 · ระแนงเลื่อน o-bsdoorprice ≈ บรรทัด 2639
ข้อมูลจำนวนบาน: ต้องเพิ่ม stepper/input จำนวนบาน (ปัจจุบัน code ยังไม่มี field นี้ใน G2 door block)

และบล็อก ครอบวงกบอลู+ดรอปพื้น ≈ บรรทัด 2691:
if(!areaOnly && !p.zipscreen) → เพิ่ม && p.cat!=='ราวบันได'
และบล็อก คาดตาราง ≈ บรรทัด 2479:
if(!p.grid && !['หลังคา','ฝ้า-ผนัง'].includes(p.cat)) → เพิ่ม ราวบันได ใน exclude list

8. Pattern ที่ใช้ซ้ำ (สรุปเพื่อ dev)

8.1 ชิปแทน dropdown (pattern ใช้ทั่ว G2)

HTML: <div class="chip-group chip-sm" id="xxx-chips"> + ปุ่ม chip แต่ละตัว
Hidden select: <select class="o-xxx" style="display:none;">
JS: onclick="chSetChip(this,'o-xxx')" (ฟังก์ชันเดิมใน index.html)
ชิปที่ active: class on · ค่า: data-val="..."

8.2 กล่อง override ราคาประตู (สีส้ม)

โชว์เมื่อ: เลือก o-doortype หรือ o-bsdoor ≠ ""
ประกอบด้วย:
  • input o-doorprice / o-bsdoorprice (ราคาเต็ม · บาท)
  • stepper input o-door-panels (จำนวนบาน 1–4)
  • span แสดง auto price = 18000 + (n-1)*16000
  • คำแนะนำ: บานเดี่ยว ≥ 18,000 · บานที่ 2+ 16,000/บาน

8.3 <details> พับ option รอง

class optbox ที่มีอยู่แล้ว หรือสร้าง <details class="extra"> ใหม่
รวม: รื้อของเดิม (o-removeold) · งานเสริม/วิศวกรรม (o-extrawork) · ครอบวงกบ (o-fcm)
default: ปิด (open attribute ไม่ใส่)

8.4 cascade product (ระแนง)

แทนที่ product dropdown 1 ตัวขนาดใหญ่ด้วยการ drill-down:
step 1 — หมวด chip (บังตา/ผนัง)
step 2 — profile dropdown (1×5, 1"×1.6", ...)
step 3 — chip ช่อง (2/3/5 cm. + ทึบ) + chip โครง (ไม่โครง/รวมโครง)
→ 3 ค่า map เป็น product id (rn1–rn88) ผ่าน lookup table ใน JS

9. จุดที่ยังต้องให้พี่นัทตัดสิน

#ประเด็นเลือก
1 ระแนงเลื่อน (bar_slide): ปัจจุบัน "ค่าประตู" เลือกรุ่นบาน (dropdown รุ่น) แล้วคำนวณเอง — ควรเปลี่ยนเป็นกรอกราคาอย่างเดียว (override เต็ม) หรือยังให้เลือกรุ่นได้? รอมติ (draft ทำทั้งสอง — เลือกรุ่น + override)
2 ระแนง-บังตา: profile "1×5 cm." มีตัวเลือกช่องโชว์เป็น 1 cm. หรือ 5 cm. — ดราฟใช้ chip ช่อง แต่ใน dropdown เดิม "ช่องโชว์" ไม่ได้ระบุชัด ในชื่อรุ่น (rn1 = 1 ช่อง 5 cm., rn7 = 5 ช่อง 5 cm.) — cascade นี้ถูกต้องไหม? รอยืนยัน mapping profile↔id จากพี่นัท
3 ราวกันตก imp1/4 บรรทัด detail: "อุปกรณ์มาตรฐานผู้ผลิต สแตนเลสสีเงิน" (บรรทัด 1) + "หมุดสแตนเลสสีเงิน" (บรรทัด 2) — ตัด "สแตนเลสสีเงิน" ออกจากบรรทัดแรกตามมติ R4 ยืนยันไหม? ยืนยันแล้วตามมติ R4 · dev แก้ได้เลย
4 ราวกันตก IMP rates ในดราฟใช้ราคา dummy (5,000–7,000/ม.) — ต้องตรวจสอบกับ RATES จริงใน code (RATES['IMP1'] ฯลฯ) ก่อน dev ทำ cascade dev ใช้ RATES จาก index.html โดยตรง · ดราฟ = demo ราคาไม่จริง
