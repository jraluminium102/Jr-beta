## Root Cause (จากอ่าน source local)

### บั๊ก 1 (`subitem-wrap`)
- **template `addItem()`** สร้าง HTML โดยมี `.subitem-wrap` เปิดเสมอ (ไม่มี guard)
- **`buildItemOpts(d)`** L4241–4243 มี fix ซ่อนเมื่อ `_famGrp !== '1'` อยู่แล้ว
- **แต่ live site ยังเห็นบั๊ก** → แสดงว่า fix นั้นยังไม่ deploy หรือ `buildItemOpts` ไม่ถูกเรียก
- ต้องตรวจ: เมื่อกด group chip แล้ว `buildItemOpts` ถูก dispatch ไหม (ดู L4071-4074)

### บั๊ก 2 ("ล็อค·มุ้ง·คาดตาราง")
- oc-block accordion โผล่ก็ต่อเมื่อมี option item ตรงกับ keyword
- Local code L4592: `if(!p.grid && !p.handrail && !p.zipscreen && !['หลังคา','ฝ้า-ผนัง','shower','มุ้ง','ระแนง',...].includes(p.cat))` → guard อยู่แล้ว
- แต่ G2 ราวกันตก / G4 ตู้ยังมีตัวเลข "(2)" ใน accordion บน live site → ต้องตรวจว่า option ใดหลุดผ่าน

### ขั้น 2: แก้ช่องว่างที่ยังหลุด (ถ้าพบ)

**กรณี `subitem-wrap` ยังโผล่หลัง product select:**
- ตรวจ: `addItem()` → เรียก `buildItemOpts(d)` ท้ายฟังก์ชัน (L4118) ไหม
- ถ้าเรียกแต่ยังโผล่ → ตรวจ `_famGrp` ที่อ่านได้ใน `buildItemOpts`
  ```javascript
  var _famGrp=(d.querySelector('.i-group')||{}).value||'1';
  ```
  ค่า default เป็น `'1'` → ถ้า `.i-group` ไม่มีใน DOM ตอน addItem จะ default เป็น G1 → ซ่อนไม่ได้
- Fix: ใน `addItem()` ตั้ง `.subitem-wrap` เป็น `display:none` ก่อน แล้วค่อย `buildItemOpts` toggle

**กรณี "ล็อค·มุ้ง·คาดตาราง" accordion ยังโผล่ใน G4/G5:**
- ดู option ไหนที่ตรง keyword → อาจเป็น "มือจับ" ที่ G4 generate
