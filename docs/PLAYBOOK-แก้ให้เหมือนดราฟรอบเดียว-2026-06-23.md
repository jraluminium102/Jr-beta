# 🎯 PLAYBOOK — แก้งานให้เหมือนดราฟ "รอบเดียวจบ"

> ปัญหาที่เจอซ้ำ: สั่งแก้ทีไร ต้องแก้ 3+ รอบกว่าจะเหมือนดราฟที่ออกแบบไว้ · เอกสารนี้ = วิธีทำให้จบรอบเดียว + แพทเทิร์นมาตรฐาน

---

## 1. ทำไมแก้หลายรอบ (สาเหตุจริงที่เจอ)

| สาเหตุ | ตัวอย่างที่เคยพลาด |
|---|---|
| ใบสั่งกำกวม — dev ตีความเอง | "ทำสีให้ครบ" → dev เดาว่าครบแค่ไหน |
| ดราฟไม่ใช่ต้นแบบที่กดได้ | อธิบายเป็นคำ → dev นึกภาพไม่ตรง |
| ไม่ระบุ before/after เป๊ะ | ไม่รู้โค้ดเดิมตรงไหน แก้ผิดจุด |
| เชื่อ audit script ดิบ | false positive เยอะ (เทสผิด product · hidden≠removed) → แก้ของที่ถูกอยู่แล้ว |
| ลืมเทสเว็บสด vs ดราฟ | เคลม "เสร็จ" จาก jsdom → จริงๆ หน้าตาไม่ตรง |
| เดาข้อมูล (สี/เรต/กระจก) | ใส่ไม่ครบ/มั่ว → พี่ต้องสั่งแก้ซ้ำ |

---

## 2. วิธีแก้ให้จบ "รอบเดียว" (SOP — ทำทุกข้อก่อนส่ง dev)

1. **ดราฟ approve = ต้นแบบเป๊ะ** — dev เปิด"กดเล่นดูพฤติกรรมจริง" (ไม่ใช่อ่านคำอธิบายแล้วเดา)
2. **ใบสั่งทุกจุดมี 4 อย่าง:** พิกัดบรรทัด + `before` (โค้ดเดิม) + `after` (ที่ต้องการ) + **เกณฑ์ผ่าน** (เทสอะไรถึงเรียกว่าถูก)
3. **ระบุ "ห้ามแตะอะไร"** — golden 150/150 · กลุ่มอื่นไม่เปลี่ยน · โหมดเร็วไม่พัง
4. **ดึงข้อมูลจริงจาก index.html ไม่เดา** — สี/กระจก/เรต/ชื่อ ดึงจาก COLORS/GLASS/PRODUCTS จริง · ใส่ให้ครบ
5. **verify โค้ดจริง ไม่เชื่อ audit script ดิบ** — ทุกจุดที่จะบอก "ผิด" ต้อง render จริง + เลือก product ให้ถูกตัว + เช็ก computed display จริงก่อน
6. **ไม่ชัด = ถามก่อน ห้ามเดา** (ถามสั้น + ตัวเลือก + ป้ายแนะนำ)
7. **Checklist ติ๊กก่อน push** — แนบท้ายใบสั่งทุกครั้ง

## 3. 🔍 แก้เสร็จ → ตรวจเว็บสด vs ดราฟ "ทุกครั้ง" (บังคับ · ห้ามข้าม)

หลัง dev แก้ ก่อนบอก "เสร็จ" → **เปิดเว็บสดจริง เทียบดราฟทีละจุด:**

- [ ] เปิด calculator เว็บสด (preview/localhost) เลือกชนิด/กลุ่มที่แก้
- [ ] เปิดดราฟที่ approve คู่กัน
- [ ] เทียบทีละจุด: **ปุ่ม/ชิป/dropdown · ค่าเริ่มต้น · ลำดับ · ข้อความ · การโผล่/ซ่อน · ราคา**
- [ ] เก็บหลักฐาน (screenshot / DOM eval / ราคา breakdown)
- [ ] ผ่านครบทุกจุดในดราฟ → ค่อยบอกเสร็จ · เจอไม่ตรง → แก้ก่อน ไม่ปล่อย

> ⛔ ห้ามเคลม "เสร็จ/ผ่าน" จาก jsdom อย่างเดียว — ต้องกดเว็บสดจริง (screenshot ค้างได้ → ใช้ DOM eval เทียบแทน)

## 4. ⭐ แพทเทิร์นการแก้ — "บอกแค่ 'แก้ G_' = รู้เลยต้องเตรียมแก้อะไร"

ทุกกลุ่ม (G1–G7) เวลาแก้ฟอร์ม/ใบ ให้เช็ก **4 ส่วนนี้เสมอ** (ไม่ต้องบอกซ้ำ):

### ① ฟอร์ม / ปุ่มกด
- ชนิด/รุ่น/ขนาด/ลักษณะเปิด/ราง/ล็อค = ชิป หรือ dropdown ตามดราฟ
- **ค่าเริ่มต้น (default) ถูก** (เช่น ลักษณะเปิด=เลื่อน · ล็อค=มีกุญแจ)
- ตัวเลือก ≤5 = ชิป · เยอะ (>10 ใช้ไม่บ่อย) = dropdown + optgroup
- chip ON sync ตาม value · ไม่มีปุ่มซ้ำ/มั่ว

### ② L1 / L2 / L3 สี + กระจก
- **L1 สีตามทั้งใบ** (checkbox · default ติ๊ก) → คิดสีหัวใบ · **บวกยอด**
- **L2 เฉพาะรายการ:** 🟢 ใช้จริง (บวกยอด) / 🔵 ออปชั่น (OPTION line · ไม่บวก)
- **L3 เทียบ** (พับ · ไม่บวกยอด · OPTION "เปลี่ยน X→Y ±Z")
- **สีอลูครบ** (13 · จัดหมวด) + **ช่องกรอกรหัสสี** (เฉพาะสีอบพิเศษ/ลายไม้อบ/ชุบ) + **สเปกกระจกครบ** (66 · dropdown)
- ⚠️ value option "ไม่เทียบ" = `-1` (อย่าใช้ 0 ชนสีอบขาว) · engine check `>=0`
- G4: สีโครง (rn90×อลู) + หน้าบาน (FT) **แยกกัน** · ผนังกระจก/สมาร์ท = ไม่คิดค่าสี

### ③ บล็อกใบเสนอราคา (5 บล็อก)
1. หัว: ชื่อสินค้า + ขนาด + รุ่น
2. รายการงาน: รายการ/มุ้ง/ล็อค/ครอบวงกบ/คาดตาราง
3. **OPTION line** (L2🔵 + L3 · ไม่บวกยอด)
4. หมายเหตุ (เมื่อกรอก)
5. รายละเอียด: สีอลู + กระจก (หนา+สี) + สเปค
- แยก **"รายการบน (รูปแบบงาน) / รายละเอียดล่าง (สเปค)"** · สีพิเศษมีรหัส · ข้อความน่าอ่าน ไม่ raw

### ④ อื่นๆ + ตาข่ายกันพัง
- มุ้ง / ล็อค / มือจับ (สแตนเลส 6 ขนาด+สี) / ครอบวงกบ / ดรอปพื้น / หมายเหตุ
- **การ์ดราคา sticky ขวา** (ต่อรายการ)
- **golden-snapshot 150/150** (ราคา base ไม่เพี้ยน)
- **กลุ่มอื่น (G2-G7) + G6 ห้องกระจก ไม่เปลี่ยน** (component ร่วม — เทสด้วย)
- **โหมดเร็ว (.qi-) ไม่พัง**

## 5. 🤝 เรียก subagent ที่เหมาะ "ทุกครั้งที่แก้/ตรวจ" (บังคับ)

ห้ามทำคนเดียวทุกอย่าง — แต่ละงานเรียก subagent เฉพาะทางมาช่วย · Chat A คุม/รวมผล/ตัดสินใจ

| งาน | subagent ที่เรียก | ทำอะไร |
|---|---|---|
| **แก้โค้ด index.html** | `calculator-dev` | แก้ตามใบสั่ง + golden + รายงาน (ไม่ push · Chat A ตรวจก่อน) |
| **ตรวจฟอร์ม/ปุ่มเหมือนดราฟไหม** | `draft-fidelity-checker` | render เว็บสด เทียบดราฟ ทีละปุ่ม → 🟢ตรง/🔴ขาด/🟠เกิน |
| **เช็กราคาเพี้ยน / golden** | `price-guardian` | golden 150/150 ก่อน-หลัง · จับราคาลามกลุ่มอื่น |
| **ตรวจใบเสนอราคา/บล็อก/ออปชั่น** | `quote-fidelity-auditor` / `doc-option-auditor` | render ใบจริง เทียบใบจริง · บล็อก/ราคา/ออปชั่นครบไหม |
| **ทำดราฟ UX / redesign ฟอร์ม** | skill `draft-ux-g` / `ux-designer` | ดราฟกดเล่นได้ ตามสไตล์ JR |

**กฎ:**
- 🟢 verify ที่ subagent แจ้งเสมอ (audit script หลอน false positive เยอะ — Chat A เช็กโค้ด/เว็บจริงซ้ำก่อนเชื่อ)
- เรียกหลายตัวขนานได้ (เช่น ตรวจฟอร์ม + ตรวจใบ พร้อมกัน) แล้วรวมผล
- subagent แก้/ตรวจ READ-ONLY ตามบทบาท · Chat A เป็นคนตัดสิน + push
