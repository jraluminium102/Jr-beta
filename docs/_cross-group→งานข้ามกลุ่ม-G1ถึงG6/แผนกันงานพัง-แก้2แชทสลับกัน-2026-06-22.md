# แผนกันงานพัง — เวลาแก้ `index.html` 2 แชทสลับกัน (22 มิ.ย.)

> ปัญหา: `public/calculator/index.html` ไฟล์เดียว · ตอนนี้ **คิวกลางแก้ G1** + **แชทนี้ (G2)** จะแก้ต่อ → ถ้าแก้พร้อมกัน/ไม่ระวัง = **ชนกัน (merge conflict) หรือทับงานกัน**
> หลัก: **1 ไฟล์ = 1 มือต่อครั้ง** · ดู [[why-work-breaks-shared-arch]] · [[deploy-workflow-chatB]]

---

## กฎเหล็ก 5 ข้อ
1. **ใครถือไฟล์อยู่ ทำให้จบ+push ก่อน** อีกแชทค่อยต่อ — **ห้ามแก้ index.html พร้อมกัน 2 แชท**
2. **ก่อนเริ่มแก้ทุกครั้ง:** `git pull --rebase --autostash origin main` → ดึงงานล่าสุด (เผื่ออีกแชท push ไปแล้ว) **ก่อนแตะไฟล์**
3. **golden ก่อน-หลัง:** `node scripts/golden-snapshot.mjs` ก่อนแก้ (จำ baseline) + หลังแก้ (ราคาเพี้ยน=ธงแดง หยุด)
4. **ระหว่างรออีกแชท:** ทำได้แค่ **docs/ดราฟ/เทส (read-only index.html)** — ห้ามแก้ index.html
5. **push ทันทีเมื่อจบก้อน** — ไม่ดองงานค้างใน working tree (ยิ่งดอง ยิ่งชนตอน rebase)

---

## ขั้นตอนเมื่อถึงคิวแก้ (ไฟล์ว่างแล้ว)
1. `git pull --rebase --autostash origin main` (ดึง G1 ล่าสุด)
2. `node scripts/golden-snapshot.mjs` → จด baseline (ควร 150 ตรง)
3. แก้ index.html (ทีละก้อนเล็ก · จุดที่ G2 ไม่ทับโซน G1)
4. `node scripts/golden-snapshot.mjs` → ราคาตรง baseline (ถ้าเพี้ยน=ตรวจ)
5. `node scripts/test-g2-quotes-all.mjs` → ใบ G2 ยังถูก
6. add → commit → `git pull --rebase --autostash origin main` → push HEAD:main
7. ถ้า **conflict ตอน rebase:** ดูทีละ hunk · เก็บงานทั้ง 2 ฝั่ง (G1+G2 คนละจุด) · รัน golden ซ้ำ · ห้าม `--force`
