### 1. ปุ่ม "ไปขั้นต่อไป" ใช้ได้จริงแค่ ADMIN — แต่ระบบเปิดให้ SALES/DESIGNER กด → เด้ง forbidden
- **ไฟล์:** [`supabase/migrations/0014_journey_state_machine.sql:51`](supabase/migrations/0014_journey_state_machine.sql:51) เทียบกับ [`src/app/api/jobs/[id]/advance/route.ts:15`](src/app/api/jobs/[id]/advance/route.ts:15) + [`src/components/jobs/StageAdvanceButton.tsx:8`](src/components/jobs/StageAdvanceButton.tsx:8)
- **อาการ:** RPC `advance_stage` บังคับ `if not public.has_role('ADMIN') then raise exception 'forbidden: ต้องเป็น ADMIN'` แต่ BFF เช็คแค่ `requirePermission("jobs","write")` ซึ่ง MATRIX ให้ ADMIN/SALES/DESIGNER และ `StageAdvanceButton` ไม่ gate role เลย → SALES/DESIGNER กดปุ่มผ่าน BFF แต่ถูก RPC เด้ง (ใช้ user-scoped client, `auth.uid()` = ตัวจริง). ผลคือ **flow 24 ขั้นเดินด้วย manual ได้แค่ ADMIN** ขัดดีไซน์ที่แต่ละ role ขับขั้นของตัวเอง (goal [1])
- **เสนอแก้ (เลือก 1):** ผ่อน RPC เป็น `has_role('ADMIN','SALES','DESIGNER','PRODUCTION','INSTALLER')` ตามช่วง stage **หรือ** บีบ BFF/ปุ่มเป็น ADMIN-only ให้ตรงกัน

### 2. สร้างใบวางบิลล้มเหลวทั้งใบ เมื่อยอดสุทธิมีเศษสตางค์
- **ไฟล์:** [`src/lib/money.ts:61`](src/lib/money.ts:61) + [`src/app/api/billing-notes/route.ts:80`](src/app/api/billing-notes/route.ts:80) + constraint [`supabase/migrations/0026_finance_bridge.sql:76`](supabase/migrations/0026_finance_bridge.sql:76)
- **อาการ:** `billing_notes.total = q.net` (อาจมีทศนิยม) แต่ `suggestInstallments` ทำ `Math.round(net)` ก่อนแบ่งงวด → ผลรวมงวด = round(net). ถ้า net เพี้ยนจากจำนวนเต็ม > 0.01 บาท (เกิดเมื่อ subtotal ไม่กลม + มีส่วนลด % เช่น 67,333 × 2%) constraint `tg_check_installment_sum` (tolerance 0.01) จะ `raise exception` → insert งวดล้ม → โค้ดลบหัวบิลทิ้ง (`route.ts:101`) → ลูกค้าวางบิลใบนั้นไม่ได้เลย
- **เสนอแก้:** set `total` = ผลรวมงวดที่ปัดแล้ว: `total: suggestInstallments(net).reduce((s,p)=>s+p.amount,0)` (จุดเดียวจบ)

## 🟡 น่าสงสัย (เช็คซ้ำ / บางข้อต้องต่อ DB จริงถึงปิดจบ)

### 3. computeTotals: VAT/หัก ณ ที่จ่าย ปัดบาทเต็ม แต่ total มีทศนิยม → net มีเศษได้ (ต้นเหตุข้อ 2)
- **ไฟล์:** [`src/lib/money.ts:34`](src/lib/money.ts:34)
- **อาการ:** ลำดับ subtotal→ส่วนลด→VAT→WHT→net **ถูกหลักภาษี** ✓ แต่ `total = after_discount(2 ทศ) + vat(บาทเต็ม)` → net = round2(total − wht) มีทศนิยมได้ → ไหลเข้าข้อ 2
- **เสนอแก้:** พิจารณา `roundBaht(net)` ปลายทางให้ลงตัวบาทตามเอกสารจริง (แล้วข้อ 2 หายไปด้วย)

### 4. `STAGE_FORM` ถูกประกาศแต่ไม่มีใครใช้ — ปุ่ม advance defer แค่ stage 8/20
- **ไฟล์:** [`src/lib/stages.ts:35`](src/lib/stages.ts:35) (ไม่ถูก import ที่ไหนเลย) เทียบ [`src/components/jobs/StageAdvanceButton.tsx:16`](src/components/jobs/StageAdvanceButton.tsx:16)
- **อาการ:** คอมเมนต์บอก "ปุ่มทั่วไปจะชี้ไปฟอร์มเฉพาะแทน advance ตรง" แต่โค้ดจริง defer เฉพาะ `next===8` (มัดจำ) กับ `next===20` (พร้อมติดตั้ง). stage 9–19, 21–23 ที่ map เป็นฟอร์ม production/installation กลับโชว์ปุ่ม advance ตรง (และล้มตามข้อ 1 สำหรับ non-admin)
- **เสนอแก้:** ให้ปุ่มอ่าน `STAGE_FORM[next]` เพื่อ defer ทุก stage ที่เป็นฟอร์ม ไม่ hardcode แค่ 8/20

### 5. stage 8 (ลูกค้ามัดจำ) ไม่เคยเป็นสถานะพัก — มัดจำกระโดด 7→9

- **เสนอแก้:** ยืนยันกับพี่นัทว่าตั้งใจข้าม หรือให้พัก stage 8 ก่อนค่อยเลื่อน 9 ตอนเริ่มวัด
