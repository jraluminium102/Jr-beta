1checkbox-reveal ซ่อนราง: o-rfgch default value="10" รั่วเข้า calc ถ้า rfgcl ถูกกรอก

ปิดซ่อนราง (.o-rfgc-reveal) ซ่อนอยู่จนกว่าติ๊ก .o-rfgc-toggle
แต่ภายใน span ที่ซ่อน ช่อง o-rfgch มี value="10" (สูง ซม.) ไม่ใช่ 0
calc บรรทัด 1500: _gh = (parseFloat(optSel.rfgch)||0)/100 = 0.1 เสมอแม้ไม่ติ๊ก toggle
เงื่อนไขคิดเงิน: if((_gw+_gh)>0 && _gll>0) — ถ้า rfgcl มีค่า (เช่นหลังจาก edit แล้ว uncheck) จะคิดเงินผิด
ทดสอบ edge case: user ติ๊ก กรอก gcl=10 แล้ว uncheck toggle → gcl ยังมีค่า 10, gh=10 → gc = (0+0.1)×10×3500×0.7 = 2,450 บาท โดยไม่ได้ติ๊ก

แก้: ใน onchange ของ toggle เพิ่ม reset ค่า rfgcw=0 และ rfgcl=0 เมื่อ uncheck — หรือ readItem ตรวจ toggle.checked ก่อนอ่าน rfgcw/rfgch/rfgcl

5o-rfchain (โซ่รางน้ำ 3,000/เส้น) กับ o-guttersys=โซ่ — ซ้ำซ้อนหรือต่างกัน?

มีสอง field เกี่ยวโซ่:
- o-guttersys = ชนิดระบบระบาย (ท่อ/โซ่) — label ลงใบ, ไม่คิดเงิน (readItem เก็บเป็น rfgutsys ไม่เข้า calc ราคา)
- o-rfchain = โซ่รางน้ำ (3,000/เส้น) — ของเสริม คิดเงิน
สรุปเบื้องต้น: ไม่ซ้ำกัน — guttersys=โซ่ บอกว่า "ใช้โซ่แทนท่อ", rfchain คือจำนวนเส้นโซ่ที่ซื้อเพิ่ม
แต่ UX อาจสับสน: user เลือก guttersys=โซ่ แล้วต้องไปกรอก rfchain แยก และ R3.9 ระบุ "โซ่รางน้ำ 3,000/เส้น" โดยไม่แยก 2 field

(เช็คซ้ำ) ถาม: guttersys=โซ่ ควรผูก rfchain auto ไหม หรือ user ต้องกรอกแยก
6สูตรปิดซ่อนรางน้ำ: ระบบใช้ 0.7 (ลด 30%) แต่ R3.9 บอก "x50%" (ลด 50%)
