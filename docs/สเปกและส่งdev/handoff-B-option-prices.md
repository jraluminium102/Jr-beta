## F2 🔧 redesign ช่อง OPTION (ทางเลือกลูกค้า) ต่อบาน
**ปัญหาเดิม:** มีหลายช่องทับกัน (OPTION สำเร็จรูป ~1880-1895 · ช่องโน้ต 1960 · ±บาท) → ซ้ำ "OPTION : OPTION :" + รก

**ดีไซน์ใหม่ (พี่นัทเคาะ):** 1 บล็อกพับได้ใต้บาน · cascade 2 ชั้น
```
[ + OPTION ทางเลือกลูกค้า ]   ← พับ default เห็นแค่ปุ่ม

กดเปิด 1 แถว:
หมวด [เปลี่ยนกระจก ▾ ]  รายการ [เทมเปอร์ใส 6มม. ▾]  ±บาท [auto −7,000]  [✏️ แก้ข้อความ]
→ ออกใบ: "OPTION : เปลี่ยนเป็นกระจกเทมเปอร์ใส 6 มม. (ราคา −7,000)"
[ + เพิ่ม OPTION อีก ]   ← หลายตัวได้
```
**สเปก:**
1. **พับ default** (โชว์แค่ปุ่ม) — ฟอร์มไม่รก
2. **หมวด** (6 ตัว · พี่นัทเคาะพอแล้ว): เปลี่ยนกระจก / เปลี่ยนผ้ามุ้ง / เปลี่ยนสีอลู / เปลี่ยนมือจับ / เปลี่ยนหลังคา / อื่นๆ (พิมพ์เอง)
3. **รายการ** = filter ตามหมวด · **ดึงลิสต์จริงในระบบ** (กระจก=GLASS array ~504-545 · ผ้ามุ้ง=MOSQUITO_SCREENS 798 · สี=COLORS 846 · มือจับ=ตารางข้อ4) · ใช้ `<optgroup>` แบ่งหัวข้อย่อย (กระจก: ใส/เทมเปอร์/ลามิเนต/อินซูเลท) ลิสต์ยาวก็ไม่ปน
4. **auto ข้อความ + ราคา:**
   - ข้อความ = "เปลี่ยนเป็น{ชื่อที่เลือก}" (แก้เองได้)
   - **±บาท = (ราคาขายตัวใหม่ − ตัวเดิม) × พื้นที่บาน** (พี่นัทยืนยันสูตรนี้) · แก้เองได้
5. ระบบเติม "OPTION : " หัวบรรทัดเอง → **ผู้ใช้ไม่พิมพ์ "OPTION :"** → หมดปัญหาซ้ำ
6. ของเดิม (OPTION สำเร็จรูป / ช่องโน้ต placeholder "OPTION :") → ยุบรวมเข้าบล็อกนี้ · เลิก placeholder ที่ให้พิมพ์ "OPTION :"

**หมายเหตุ:** หมวด "เปลี่ยนมือจับ" คิดราคาเป็นเหมา/ชุด (ตารางข้อ 4) ไม่ใช่ ×พื้นที่ — เช็ค logic ราคาต่อหมวด (กระจก/ผ้ามุ้ง/สี = ×พื้นที่ · มือจับ = เหมา)
