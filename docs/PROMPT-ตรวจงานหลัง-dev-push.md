```
ตรวจงานกลุ่ม G5 (มุ้ง) หลัง dev push index.html ขึ้นเว็บ — READ-ONLY ห้ามแก้ index.html

เป้าหมาย: เทียบ ปุ่ม + ออปชั่น + ราคา + อุปกรณ์เสริม ของ engine จริง (index.html ล่าสุด)
ว่าตรงกับ "ดราฟ/มติล่าสุด" ไหม · ไม่มีอันมั่ว/ผิดที่/ผิดกลุ่ม/หล่น

ทำตามนี้:
1. หา "ความจริงที่ควรเป็น" จาก:
   - ดราฟล่าสุด: docs/กลุ่ม5-มุ้ง/DRAFT-G5-ux-FULL-*.html
   - มติ + จุดแก้: memory (g5-mosquito-formux) + docs/กลุ่ม5-มุ้ง/HANDOFF-*
   - เรตจริง: docs/กลุ่ม5-มุ้ง/REF-G5-* + index.html

2. render ทุกสินค้าในกลุ่มจาก index.html จริง (node + jsdom):
   - addItem → เลือกกลุ่มงาน 5 → วนทุกรุ่น
   - ดึงต่อสินค้า: ปุ่มหมวด+รุ่น (drill-down) · control ออปชั่น (.o-*) · label.opt (หัวข้อ) · ราคา (calcUnit)

3. ออกตาราง crosscheck ต่อสินค้า — 3 สถานะ:
   🟢 ตรง (ดราฟมี · engine มี ถูกที่)
   🔴 หล่น (ดราฟ/มติมี · engine ไม่มี → ต้องเพิ่ม)
   🟠 เกิน/ผิดที่ (engine มี · ไม่ควรมี หรือผิดกลุ่ม/ผิดสินค้า → ต้องตัด/ย้าย)

4. เช็คเพิ่ม (สำคัญ — ที่มักผิด):
   - ปุ่มหมวด/รุ่น ครบ+ถูกไหม (เช่น G5 = 4 หมวด เฟรม/จีบ/จีบม่านรังผึ้ง/ม้วน · จีบ 3 รุ่น · นิรภัย=ตัวเดียว · imp31/32/33/35 ซ่อน)
   - ออปชั่นโผล่ "ถูกสินค้า" ไหม: ผ้ามุ้ง=เฉพาะเฟรม · สีกรอบมุ้ง=เฉพาะ mscolor · ครอบวงกบ=ทุกตัว · นิรภัยห้ามมีผ้ามุ้ง/สีกรอบ
   - ราคาตรง engine ไหม: รัน node scripts/golden-snapshot.mjs (ต้อง "ไม่มีความเปลี่ยนแปลง") + test/calc-mosq-frame.mjs
   - อุปกรณ์เสริมอยู่หมวดถูกไหม (ไม่ใช่ของกลุ่มอื่นมาปน)

5. สรุป: จุดผิดเรียง 🔴→🟠 · 1 จุด = สินค้า + ออปชั่น + ควรเป็นอะไร + จุดแก้ในโค้ด (ตัวแปร/บรรทัด) → ทำ HANDOFF ส่ง dev

6. กฎเหล็ก:
   - ห้ามเดาราคา/ออปชั่น — ยึด index.html + ดราฟ + REF เท่านั้น
   - ไม่ชัวร์ว่าออปชั่นควรมี/ตัด/ผิดที่ → list มาถามก่อน ไม่ตัด/เพิ่มเอง
   - แนบตาราง crosscheck เป็นหลักฐาน (สินค้า × ออปชั่น จริง vs ควรเป็น)
```
