TOP 5 — จุดที่กระทบ usability มากสุด

  1. P1 รก/งง G3 ของเสริมหลังคา 9 รายการ อยู่นอกกล่องพับ — field เสาแผง/คานเหล็กถัก/เสริมเพลท/เหล็กดึง/ซ่อนสโลป/ปิดซ่อนราง/ครอบคาน/วัสดุปิดรอยต่อ/โซ่รางน้ำ/ครอบท่อ PVC ถูก inject ตรงๆ ใน h โดยไม่มี wrapper แต่อาศัย groupGHOpts จัดเข้ากล่อง "ของเสริมหลังคา" ซึ่ง default open=false ถูกต้อง แต่ถ้า groupGHOpts ทำงานผิดพลาด (keyword match พลาด) 9 รายการจะตกไปกล่อง "งานพิเศษ·รื้อ" หรือโผล่ออกมาพร้อมกัน — ผู้ใช้เห็น field ยาวมากก่อนเลื่อนถึงราคา
    แนวทาง: ใส่ class ตรงเช่น class="rf-extra-item" บน label 9 ตัวนี้ ให้ groupGHOpts match ด้วย class แทน keyword — ป้องกัน false-positive
  2. P1 งง G3 ชิปปลายหลังคา label "ปิดปลายกันน้ำกระเด็น" ยาวเกิน 1 บรรทัดบนมือถือ — ชิป 3 ตัวในแถวเดียว (ปล่อย/มีรางน้ำ/ปิดปลายกันน้ำกระเด็น) บนจอ 360px: ตัวที่ 3 wrap ลงบรรทัดใหม่โดดเดี่ยว ดูเหมือนอีก field
    แนวทาง: ตัดให้สั้น เช่น "ปิดปลาย" แล้วใส่ hint ใต้ชิปว่า "(กันน้ำกระเด็น)" หรือตั้ง flex-wrap:wrap และกำหนด min-width ชิปให้ wrap สวย
  3. P2 สับสน G4 hint สี "สีอลู กระทบเฉพาะโครงตู้" อยู่ห่างจาก dropdown สี — dropdown สีอลู (.i-color) อยู่ในฟอร์มหลักเหนือ .i-opts แต่ hint .cab-color-hint อยู่ใน groupGHOpts กล่องตู้ ผู้ใช้อาจไม่รู้ว่า hint นั้น refer ไปถึง dropdown ด้านบน
    แนวทาง: ย้าย/ซ้อน hint เล็กๆ ไว้ใต้ dropdown สี (inject ด้วย cabUpdateHints ที่รันอยู่แล้ว) แทนที่จะอยู่ในกล่องตู้ด้านล่าง
  4. P2 พลาดง่าย G5 มุ้ง (in-panel) ผ้ามุ้ง select ยังเป็น dropdown ไม่ใช่ชิป — ส่วนมุ้งในบานอื่น (p.mosquito) ยังใช้ <select class="o-mosqfabric"> แบบ dropdown ธรรมดา ต่างจาก G5-standalone ที่เป็นชิปผ้า+ชิปสีผ้าผูกกัน — ประสบการณ์ไม่สม่ำเสมอ
    แนวทาง: แปลง o-mosqfabric ใน p.mosquito block ให้เป็นชิปแบบเดียวกับ G5-standalone พร้อม mosqFabricColors() cascade สีผ้า
  5. P2 ไม่สม่ำเสมอ G3 ระบบระบาย (ท่อ/โซ่) ชิปสีท่อ/ลายโซ่ซ้อนกัน 2 ชั้นในบรรทัดเดียว — label "ระบบระบาย" มีชิปท่อ/โซ่ + ชิปสี inline ในบรรทัดเดียว เมื่อเลือก "โซ่" ต้องเลือก ลาย+สีโซ่ด้วย ทั้งหมด fit ใน 1 <label> ทำให้แน่น — บนมือถือ 360px อาจ overflow ได้
    แนวทาง: split ระบบระบาย+สีออกเป็น 2 label/แถว หรือใช้ reveal-block เหมือน o-guttersys-wrap pattern

G3 — หลังคา / ฝ้า-ผนัง

1. แท็บ หลังคา/ฝ้า-ผนัง + drill-down กลุ่มวัสดุ→รุ่น

หัวข้อสถานะข้อเสนอ
แท็บ 2 ตัว (หลังคา/ฝ้า-ผนัง) ดี — ชิป min-height:40px, เห็นชัด, ไม่ scroll หา —
กลุ่มวัสดุ → รุ่น (2 ชั้น) ดี — cascade ตรงตาม draft v5, default highlight จาก rfGrpOf(p.id) —
จำนวนชิปในกลุ่ม "จีบ" (G5) 9 ชิป ในแถวเดียว — เมทัลชีท/ชินโคไลท์ฯ ฝั่งหลังคาก็มีหลายตัว ถ้า >5 ชิปในกลุ่ม ควร wrap + highlight รุ่นยอดนิยม (เช่น star badge) เพื่อให้ตัดสินใจเร็วขึ้น P3
โพลีตัน — ยัง dropdown ไม่ใช่ชิป ต่างจากรุ่นอื่น — roof_polyton ใช้ <select class="o-roofcolor"> ธรรมดา (8 option ยาว) ขณะที่ไวนิล/ดีไลท์/เมทัลชีท/ชินโคไลท์ ใช้ rfChips แล้ว แปลง o-roofcolor ของ roof_polyton เป็น rfChips ด้วย (8 ตัวจัดได้ใน wrap) — ประสบการณ์สม่ำเสมอ P2

2. ปลายหลังคา 3 ชิป

หัวข้อสถานะข้อเสนอ
ชิป 3 ตัว single-select ดี — chSetChip fire change → reveal block ทำงาน —
label ชิปที่ 3 ยาว "ปิดปลายกันน้ำกระเด็น" — 14 ตัวอักษร บน 360px wrap โดดเดี่ยว เปลี่ยนเป็น "ปิดปลาย" + hint ย่อยใต้ชิปหรือ tooltip P1
auto-fill ความยาว ดี — เลือก "รางน้ำ" → o-rfgutlen auto ดึง i-w; เลือก "ปิดปลาย" → o-rfeave auto ดึง i-w —
ค่า default ปล่อย ดี — default = "ปล่อย" (เคสทำน้อยที่สุด = ไม่ต้องทำอะไร) —

3. กล่องรางน้ำ (ชนิดราง → ระบบระบาย)

หัวข้อสถานะข้อเสนอ
เรียง ชนิดราง → ระบบระบาย ดี — ตาม G3-round2 B③+D, ชิปทั้งคู่ —
ระบบระบาย + สีท่อ/โซ่ inline แน่น — ชิป ท่อ/โซ่ + span สีท่อ + span ลายโซ่+สีโซ่ อยู่ใน label เดียว ยาวมากบนมือถือ แยก "สีท่อ" / "ลายโซ่+สีโซ่" ออกเป็น label ย่อยด้านล่าง (reveal ตาม o-guttersys) P2
ตะแกรงพลาสติก default checked ดี — สเปกพ่วงรางน้ำเสมอ, ติ๊กล่วงหน้าแล้ว ลดการกด —
ท่อน้ำทิ้ง PVC ชิปสี ดี — rfChips 4 ตัว (ไม่มี/ดำ/ขาว/เทา) default "ดำ" ตามสเปก —

4. ของเสริมหลังคา 9 รายการ (เรียง 1-9)

หัวข้อสถานะข้อเสนอ
กล่องพับ default ปิด ดี — groupGHOpts set open=false สำหรับกล่อง "ของเสริม" —
keyword matching เปราะ ความเสี่ยง — ใช้ textContent + className match keyword เช่น 'เพลท','เหล็กดึง','ซ่อนสโลป' ถ้า label เปลี่ยนคำ หรือชิปมี text ซ้อน จะตกกล่องผิด เพิ่ม class marker rf-extra บน label 9 ตัว แล้ว groupGHOpts ตรวจ k.classList.contains('rf-extra') แทน P1
ปิดซ่อนราง + ครอบคาน เป็น checkbox-reveal ดี — ติ๊กก่อนค่อยกรอก ลด clutter ตาม G3-v5 จุด2/จุด3 —
ซ่อนสโลป — 3 ช่องในบรรทัดเดียว แน่น — ชิปวัสดุ + สูง + ยาว/ด้าน + ด้าน อยู่ใน 1 label ยาวมาก ห่อ 3 ช่องตัวเลขใน span reveal (โชว์เมื่อเลือกวัสดุ ≠ "ไม่มี") P3
เสาแผง + เสา 4"x8" บรรทัดเดียว ยอมรับได้ — 2 ช่องใน label เดียว ไม่ซับซ้อน —
วัสดุปิดรอยต่อ — checkbox + ชิปสีในบรรทัดเดียว ลำดับอ่านยาก — checkbox ด้านซ้าย แต่ชิปสีโผล่ทันทีโดยไม่ hide เมื่อไม่ติ๊ก ซ่อนชิปสีจนกว่าจะติ๊ก checkbox (reveal pattern เหมือน o-rfgc-wrap) P2

G4 — ตู้อลู / ฝาตู้

1. ชิป switch สินค้า ตู้อลู/ฝาตู้

หัวข้อสถานะข้อเสนอ
ชิป สินค้า บนสุด ดี — cabProdSwitch sync .i-prod + rebuild ฟอร์ม ใช้งานได้ —
ชิปสินค้าอยู่ใน .i-opts สับสน — ชิปสินค้าอยู่ใน accordion กล่อง "รายละเอียดตู้" ซึ่ง open=true แต่ผู้ใช้ต้องเห็น ก่อน เลื่อนลงมา — เสี่ยงถูกซ่อนหาก accordion collapse ย้าย chip switch ออกนอก accordion เหมือน mosq-modeb (ใช้ skipEls ใน groupGHOpts) P2
ฝาตู้ — hint ขนาดต่อบาน ดี — "ขนาดที่กรอก = ต่อบาน · บานที่ 2-3 +5,500/บาน (max 3)" ชัดเจน —

2. วัสดุผนัง + ชนิดชั้น (บล็อกเดียว + cascade)

หัวข้อสถานะข้อเสนอ
วัสดุผนัง + ชนิดชั้น ในกล่องเดียว ดี — border:1px solid กั้น ไม่ลอยอิสระ ดูเป็นกลุ่มเดียวกัน —
cascade hint "ชั้นกระจก = ไม่คิดค่าสีโครง" ดี — cab-shelf-glass-hint โชว์/ซ่อนตาม cabUpdateHints ถูกต้อง —
hint สีกล่องฟ้า อยู่ห่าง dropdown สี งง — .cab-color-hint อยู่ใน .i-opts ห่างจาก .i-color ที่อยู่บนฟอร์มหลัก inject hint สั้น (เช่น "สีนี้ = โครงตู้เท่านั้น") ไว้ใต้ .i-color ด้วย cabUpdateHints P2

3. ลึก/ชั้นแถวเดียว + badge auto

หัวข้อสถานะข้อเสนอ
ลึก+ชั้น แถวเดียว ดี — display:flex;flex-wrap:wrap ดูสะอาด —
badge "auto" สีเขียว ดี — ชัดว่าค่า default คำนวณให้ · กรอกเองได้ —
input height:32px บน mobile เล็กกว่า 44px — o-depth, o-shelves ใช้ height:32px ไม่ถึง tap target mobile (CSS global .ch .opt input[type=number]{min-height:44px} ควร override แล้ว แต่ inline style ชนะ) ลบ height:32px inline จาก o-depth, o-shelves หรือเปลี่ยนเป็น min-height:44px P2

4. ประเภทตู้ + จำนวนบาน + ผนังหลัง tap zone

หัวข้อสถานะข้อเสนอ
ประเภทตู้ ชิป ตู้ทั่วไป/รองเท้า ดี — trigger auto สูง/ลึก ตาม o-cabtype listener —
จำนวนบาน ชิป 1/2/3 + hint ดี — hint "ยิ่งหลายบาน บานยิ่งเล็ก" ช่วยตัดสินใจ —
+ผนังหลัง tap zone ≥44px ดี — min-height:44px, border, ข้อความ 2 บรรทัด ชัดเจน —
hint ผนังหลัง "ปกติชนผนังปูน" ดี — อธิบายบริบทชัดเจน ลดคำถาม —

G5 — มุ้ง (standalone) + มุ้งใน-บาน

1. Drill-down 3 หมวด (เฟรม/จีบ/ม้วน)

หัวข้อสถานะข้อเสนอ
ชิปหมวด 3 ตัว + ชิปรุ่นใต้ ดี — cascade ถูกต้อง, mosqPickGrp เลือกรุ่นแรกในกลุ่มอัตโนมัติ —
หมวด "จีบ" มี 9 รุ่น รก — SD พื้นฐาน/ทูเวย์/ตีนตะขาบ/รังผึ้ง/Blackout/นิรภัย 2 แบบ/จีบนิรภัย = 9 ตัว เพิ่ม sub-group ใน "จีบ" เช่น SD / ตีนตะขาบ / นิรภัย เป็น 3 ชั้น หรือ highlight รุ่นขายดี เพื่อตัดสินใจเร็ว P3
default รุ่นแรกของกลุ่ม ดี — mosqPickGrp ดึง [0] ของกลุ่มใหม่ทันที ไม่ปล่อยว่าง —

2. โหมด B กล่องส้มบนสุด

หัวข้อสถานะข้อเสนอ
กล่องส้ม class mosq-modeb ดี — skipEls ใน groupGHOpts คง mosq-modeb บนสุด ไม่เข้า accordion —
border 2px orange เด่น ดี — เห็นทันทีว่า "โหมดพิเศษ" ต่างจากฟอร์มปกติ —
label โหมด B: checkbox อยู่ใน flex ดี — display:flex;align-items:center;gap:8px ชัดเจน —
ค่าเสริมกล่อง/ราง (placeholder "0 = ไม่เสริม") ดี — hint ชัดเจน ไม่ต้องอธิบายเพิ่ม —

3. ผ้ามุ้ง/สีผ้า (G5-standalone vs มุ้งใน-บาน)

หัวข้อสถานะข้อเสนอ
G5-standalone: ผ้ามุ้งชิป + สีผ้า cascade ดี — mosqFabricColors() rebuild ชิปสีตามผ้า, สีเดียว disabled+badge —
มุ้งใน-บาน (p.mosquito): ผ้ามุ้ง dropdown ไม่สม่ำเสมอ — <select class="o-mosqfabric"> ยังเป็น dropdown 5 option ไม่มีชิปสีผ้าผูก ทำชิปผ้า+ชิปสีผ้าใน mosq block เหมือน G5-standalone (ใช้ mosqFabricColors เดิมได้) P2
จำนวนบานมุ้ง ชิป auto/1..N ดี — rebuildMosqPanelChips cap ที่ i-panels, fallback stepper เมื่อ >5 —
ช่องขนาดมุ้ง ซ่อนใน details ดี — "กรณีแต่ละบานไม่เท่ากัน" พับ default ไม่รก —
สีกรอบมุ้ง ชิป 4 ตัว ดี — default "ตามสีบาน", chSetChip sync o-mosqcolor —

4. G3-round2 ของเสริมเรียง 1-9

หัวข้อสถานะข้อเสนอ
ลำดับ โครงรับ→สวยงาม→กันน้ำ/รอยต่อ ดี — เรียงตามการใช้งานจริง ช่างทำโครงก่อน ตกแต่งทีหลัง —
คานเหล็กถัก ชิป 4 ตัว + ช่องยาว ดี — rfChips("0"→ "ไม่มี") เป็น default, ช่องยาว reveal ตามค่าที่เลือก ปรับ: ซ่อน input ยาว(ม.) เมื่อเลือก "ไม่มี" เพื่อลด clutter P3
วัสดุปิดรอยต่อ — ชิปสีโผล่ทันที งง — ชิปสี ขาว/ดำ/เทา โผล่พร้อม checkbox แม้ยังไม่ได้ติ๊ก ห่อชิปสีใน reveal-span ซ่อนจนกว่า o-rfsealer checked P2

สรุปตาราง Priority รวม

Priorityฟอร์มจุดผลกระทบ
P1 แก้ก่อน G3 ชิปปลายหลังคาตัวที่ 3 ยาวเกิน → wrap โดด / keyword matching ของเสริมเปราะ ผู้ใช้งงตำแหน่ง / ตกกล่องผิด → ราคาคิดผิด
P2 ควรทำ G4 hint สี "กระทบเฉพาะโครง" อยู่ห่าง dropdown สี / o-depth:32px ไม่ถึง 44px ผู้ใช้เลือกสีโดยไม่รู้ว่าเฉพาะโครง / กดพลาดบนมือถือ
P2 ควรทำ G5/G1 ผ้ามุ้งในบาน ยังเป็น dropdown ไม่เป็นชิปสีผ้า cascade ประสบการณ์ไม่สม่ำเสมอกับ G5-standalone
P2 ควรทำ G3 ระบบระบาย ท่อ/โซ่ + สี/ลาย inline → แน่นบนมือถือ ชิปชิดกัน tap ผิด, overflow
P2 ควรทำ G3 วัสดุปิดรอยต่อ ชิปสีโผล่ก่อน tick checkbox ผู้ใช้งงว่าสีนี้เกี่ยวกับอะไร
P2 ควรทำ G4 ชิป switch สินค้า อยู่ใน accordion (เสี่ยงซ่อน) สลับตู้↔ฝาตู้ไม่สะดวก
P3 ปรับ G3/G5 กลุ่ม "จีบ" 9 ชิป / โพลีตัน dropdown / คานเหล็กถัก ช่องยาวโผล่ตลอด ตัดสินใจช้า, clutter

จุดที่ผ่านดีแล้ว (ไม่ต้องแตะ)

  • ชิป min-height:40px (chip-sm) ครบทุกฟอร์ม — tap target ยอมรับได้บนมือถือ
  • G3 แท็บ หลังคา/ฝ้า-ผนัง + cascade กลุ่ม→รุ่น ใช้งานได้ลื่น
  • G3 ปิดซ่อนราง + ครอบคาน เป็น checkbox-reveal — เห็นน้อยจนกว่าต้องการ
  • G3 auto-fill ความยาวรางน้ำ/ปิดปลาย จาก i-w — ลดการพิมพ์
